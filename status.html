이미 완성

6개 대분류 — 회귀·seed로 검증됨

  • 에러코드 진단 — lookup(exact) × RAG 이원화, 70건 실데이터
  • 부품→재고→대체품→견적 — 4개 도구 전부 DB 연동, 재고 0 시나리오 라이브 검증
  • 반복 고장 감지 — 30일/3회 실 SQL, seed 경계값까지 검증
  • 안전 경고 자동삽입 — 근거 페이지 없이는 발행 자체 거부
  • v2 판정/증빙/처분/근거계층 — 5개 서브기능 전부 실 로직
  • SSE 스트리밍 자체 — 4종 이벤트 실발행 + 실시간 타임라인 UI

조금만 더 하면 끝남

남은 작업이 명확히 좁음

  • 화면 직접 PO 초안 생성 UI — 백엔드 도구는 있음, 브랜치 목적인 화면 자체가 아직 없음(직전 커밋은 설계 문서뿐)
  • 도구 호출 "이유" 필드 — SSE에 tool/input만 있고 rationale 없음. 백엔드가 문자열 하나만 추가하면 됨
  • A2A 프로토콜/클라이언트 — 이제 커밋·테스트 완료(a2a_identity_contract 19/19). FinAllQ 어댑터 상대 실 HTTP 왕복까지 확인했지만, 인증은 여전히 의도적 스텁이고 InsuQ 쪽은 미검증
  • A2A 상담 요청 빌더 — request-withdrawal(S5)·lookup-clause에 이어 assess-loan(S8)까지 3종이 실데이터 기반으로 동작. 남은 건 실 InsuQ/FinAllQ 서버 연동 확인뿐
  • 보전지표의 잔가율 곡선 — 정률 목업 공식(의도적 고지). 실 감가 데이터가 없다는 한계가 실증돼 있음

손도 안 댐

코드 자체가 없음

  • A2A 외부 응답 표시 뷰 — frontend 전체를 grep해도 A2A/InsuQ/FinAllQ 관련 코드 0건. 응답은 traces 테이블과 콘솔 데모 출력에만 남고 화면에 렌더되지 않음
