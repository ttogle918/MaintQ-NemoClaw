# 기준내용연수 `N` — 법인세법 시행규칙 별표6 실수집 대조

> 실호출 대조 **2026-08-13**. 대상: `data/build_residual_curve.py:44`
> `STATUTORY_LIFE_YEARS = 8  # 법정 기준내용연수 N — 제조업 기계장치 (⚠ 미검증 가정)`
>
> **결론: `N = 8` 은 근거 서술도 업종도 틀렸다. → `N = 10` 으로 정정 완료 (D89).**
> 시연 공장 업종을 **한국표준산업분류 중분류 `29`**(기타 기계 및 장비 제조업)로 고정하고
> 별표6 **제5호**에서 값을 가져왔다. 영향은 §7.

---

## §1. 어느 별표인가 — 확정

`residual_curve.md` 는 근거를 *"별표5·6"* 으로 묶어 적어 두어 어느 쪽인지 특정돼 있지 않았다.
**별표서식 API(`target=licbyl`) 실호출로 확정했다.**

| 별표번호 | 별표명 | 우리 대상인가 |
|---|---|---|
| `000500` (별표5) | **건축물 등**의 기준내용연수 및 내용연수범위 | ❌ 건축물 — 무관 |
| `000600` (별표6) | **업종별 자산**의 기준내용연수 및 내용연수범위 | ✅ **이쪽이다** |

둘 다 `법인세법 시행규칙` · 제15조제3항 관련 · 공포일자 `20260701` · 개정 `2024. 3. 22.`

> **별표6 비고 1** — *"이 표는 별표 3 또는 별표 5의 적용을 받는 자산을 제외한 모든
> 감가상각자산에 대해 적용한다."* → 기계장치는 별표6 관할이 맞다.

---

## §2. 🚨 `8년` 은 "범위의 중앙"이 아니다

`residual_curve.md §2-2` 는 이렇게 적고 있다:

> 제조업 기계장치의 기준내용연수를 8년으로 두었다(**내용연수범위 6~10년의 중앙**).

**표에는 `8년`과 `(6년~10년)`이 한 칸에 함께 들어 있다.** 중앙값을 계산해서 얻은 값이 아니라
**제4호에 명시된 기준내용연수 그 자체**다. 숫자는 우연히 같지만 **근거 서술이 틀렸다** —
"중앙값으로 유도했다"고 적으면 다른 호에도 같은 방식이 적용되는 것처럼 읽힌다.

---

별표6 전문(6쪽 · 3,876자)에서 추출한 구분표다.

| 호 | 기준내용연수 (범위) | 해당 **제조업** 중분류 |

> ⚠️ 코드 주석은 `제조업 기계장치` 라고만 적혀 있는데, **별표6에 "제조업 일반" 이라는 칸은 없다.**
> 업종 **중분류**가 정해져야 `N` 이 정해진다. 같은 컨베이어라도 식료품 공장이면 10년,
> 화학 공장이면 8년이다.

## §4. 🚨 그런데 우리 데이터에 업종이 없다

`assets` 테이블 컬럼 22개에 **업종(KSIC) 필드가 없다.**

```
asset_id · name · category · line_id · building_id · acquired_at · acquisition_cost ·
book_value · status · tax_credit_applied · has_lien · lien_creditor · lien_consent_ref ·
insured · policy_id · safety_inspection_target · last_inspection_date ·
inspection_valid_until · cumulative_repair_cost · last_overhaul_at ·
controller_generation · parts_eol_flag
```

`category` 는 **중고 장터 매물 분류축**(`일반산업`·`공작 기계`·`공조냉각유공압`·`환경  설비`·`기타`)
이지 한국표준산업분류가 아니다 — `residual_curve.md §2-5` 가 이미 지적한 그 문제다.

**즉 현재 구조로는 `N` 을 법령에서 유도할 수 없다.** 시연 공장의 업종을 정하는 것이 선행이다.

> **별표6 비고 2** — *"내용연수범위가 서로 다른 둘 이상의 업종에 공통으로 사용되는 자산이
> 있는 경우에는 그 사용기간이나 사용정도의 비율에 따라 **사용비율이 큰 업종**의 기준내용연수
> 및 내용연수범위를 적용한다."* → 자산 단위가 아니라 **사업장 업종 단위**로 정해진다는 뜻이다.

## §5. 결정 — 업종 고정 (2026-08-13 · D89)

**시연 공장 업종 = 한국표준산업분류 중분류 `29` (기타 기계 및 장비 제조업)**

시드 구성이 **가공**(2번 라인 주축·절삭유) → **조립**(1·3번) → **포장**(4번) 일관 라인이고
조립라인이 4개 중 2개로 지배적이다. 후보였던 `25`(금속가공제품 제조업)도 **같은 제5호**라
`N` 은 동일하므로 이 선택이 곡선을 바꾸지 않는다.

→ 별표6 **제5호** → **`N = 10`** (내용연수범위 8~12년)

상수는 `data/build_residual_curve.py` 에 3종으로 함께 둔다 — 값만 두면 *"왜 10인가"* 가 사라진다:

```python
DEMO_PLANT_KSIC = "29"            # 기타 기계 및 장비 제조업
STATUTORY_LIFE_BYL_ITEM = 5       # 별표6 제5호
STATUTORY_LIFE_YEARS = 10         # 기준내용연수 (범위 8~12년)
```

> ⛔ **`assets` 에 `ksic_code` 컬럼을 만들지 않았다.** 별표6 **비고 2**가 *"둘 이상 업종에
> 공통 사용되는 자산은 **사용비율이 큰 업종**을 따른다"* 고 하여 **사업장 업종 단위**로
> 정해지기 때문이다 — 자산별 컬럼은 법령 구조와 어긋난다.

## §7. 바꾸고 나서 실제로 무엇이 달라졌나

| | N=8 | N=10 |
|---|---:|---:|
| 정률 상각률 `r` | 0.0830 | **0.0670** |
| 잔존율 `0-2` | 0.917 | 0.933 |
| `3-5` | 0.7071 | 0.7579 |
| `6-10` | 0.5000 | **0.5743** |
| `11-15` | 0.3242 | 0.4061 |
| `16-20` | 0.2102 | 0.2872 |
| `21-30` | 0.1146 | **0.1768** |
| `FLOOR` 구속 시작 연차 | 27 | 34 |

**`assess_repair_value` 3지 판정은 27조합 중 1건만 뒤집혔다** (9설비 × 수리비 3종 A/B 실측):

```
INV-L4-02 (4번 포장라인 랩핑기)  수리비 1,500,000원   HOLD → REPAIR_RECOMMENDED
```

자산 잔가가 더 남으니 수리가 정당화되는 방향이라 설명 가능하다.

> 🚨 **`N` 이 법령 대조를 마쳤다고 곡선이 실측이 되는 것은 아니다.**
> `RESIDUAL_AT_LIFE_END = 0.50`(세법 관행 0.05 아님) 과 `FLOOR = 0.10` 은 **여전히 근거
> 미확보 가정**이다. D74·D65 의 추정치 고지는 그대로 유지된다.

## §6. 수집 방법 — 재현용

```
목록: GET https://www.law.go.kr/DRF/lawSearch.do
      OC=<LAW_API_OC>  target=licbyl  type=JSON  query=기준내용연수  search=1  display=20
      → totalCnt=2 (별표5 000500 · 별표6 000600)

본문: ⛔ API 로 텍스트가 오지 않는다.
      lawService.do?target=licbyl&ID=18256423&type=JSON|XML|HTML 은 셋 다
      3,153자짜리 **뷰어 HTML 셸**을 돌려준다 ('제조업' 문자열조차 없다).
      → 실제 본문은 첨부파일뿐이다:
         PDF  /LSW/flDownload.do?flSeq=166450715  (192,596 bytes · 6쪽 · pdfplumber 추출 가능)
         HWP  /LSW/flDownload.do?flSeq=166450713  (67,072 bytes)
```

> 🚨 **`search` 파라미터 의미가 조문 API 와 다르다.** 조문은 `search=1` 이 법령명인데
> `licbyl` 은 **`search=1` = 별표명 · `search=2` = 법령명** 이다.
> `query=법인세법 시행규칙 & search=1` 로 부르면 **totalCnt=0** 이 돌아온다(실측).

> ⚠ **`data/rules/laws/` 에 넣지 않았다.** 그 디렉터리는 **조 단위 텍스트 + `text_hash`**
> 규격인데(`11 §2`), 별표는 조문이 아니라 **표**이고 API 가 텍스트를 주지 않아
> 같은 규격으로 담을 수 없다. 담으려면 별도 설계가 필요하다 → 백로그.
