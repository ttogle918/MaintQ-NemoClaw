# MaintQ 데이터 출처 카탈로그

> **이 문서는 "어디서 무엇을 왜 가져왔는가"의 단일 대장이다.**
> 최종 갱신 **2026-08-12**. 관련 결정: **D16**(소싱 방침) · **D19**(매뉴얼 manifest) · **D60**(원본은 파일이 정본) · **D65**(추정치 고지) · **D67**(확장 범위) · **D68**(자산 대상 재정의)
>
> 📁 **디스크에 실제로 뭐가 있는지는 [`data/raw/INDEX.md`](raw/INDEX.md) 가 대장이다.** 이 문서는 *"왜 가져왔고 어디에 쓰는가"*, 저쪽은 *"어느 디렉터리에 무엇이 있는가"* 다. 둘이 어긋나면 **디스크 실측인 `INDEX.md` 가 맞다.**

**원칙 3가지 — 데이터를 늘릴 때마다 이걸 먼저 본다:**

1. **수집은 개발 시점 작업이다.** 런타임 서버는 커밋된 스냅샷만 읽는다(`11_ASSET_LIFECYCLE §7`). 요청마다 외부 기관을 호출하면 "서명 시점 스냅샷 재현" 전제가 깨진다.
2. **원본은 파일(git)이 정본, DB 는 조회용 사본**(D60). 재적재로 복원 가능해야 하고 DB 를 지워도 근거는 남아야 한다.
3. **없는 정확도를 있는 척하지 않는다**(D65). 원천이 없으면 목업 + 고지가 정답이지, 그럴듯한 숫자를 만드는 게 아니다.

# §3. API 원천 상세

## ✅ A1 — 국가법령정보 (법제처) · 계층 1 법령 원문

| | |
|---|---|
| **신청** | [open.law.go.kr](https://open.law.go.kr/LSO/lab/lawListSupport.do) → OPEN API → 활용신청 |

| **엔드포인트** | 본문 `https://www.law.go.kr/DRF/lawService.do` · 목록 `https://www.law.go.kr/DRF/lawSearch.do` |
| **상태** | ✅ 승인 완료 · 테스트 호출 성공 (2026-08-07) |

```
https://www.law.go.kr/DRF/lawService.do
  OC=<신청 이메일 ID 앞부분>   target=eflaw   type=JSON
  MST=<법령 마스터번호>        efYd=<시행일자>   JO=<조번호>
```

**왜 받았나** — 확장 범위(D67)의 **토대**다. `11 §2` 가 세운 근거 3계층에서 계층 1(사실)을 채우는 유일한 공식 원천이고, LLM 이 법령을 지어내지 못하게 막는 장치다.

**왜 이 API 여야 하나** — 응답이 **조 단위**(`조문번호`/`조문제목`/`조문내용`/`조문시행일자`/`공포번호`)로 온다. `11 §2` 의 *"조 단위로 쪼갠다, 문서 통짜 저장은 인용 앵커를 만들 수 없다"* 와 구조가 정확히 일치한다.

**부수 수확 2건** — 따로 찾을 필요가 없었다:
- **기준내용연수** (법인세법 시행규칙 별표5·별표6) → 별표서식 API + 응답의 `별표번호`/`별표제목`/`별표내용`
- **안전검사 대상 기계 12종** (크레인·프레스·전단기·압력용기·국소배기장치·원심기·롤러기·사출성형기·컨베이어·산업용로봇·리프트·곤돌라) → 산안법 시행령 제78조가 고시로 위임하므로 `target=admrul`(행정규칙). 검사주기 = 설치 후 3년, 이후 2년

**소비처** — `data/rules/laws/*.json` 의 `text`·`effective_from`·`promulgation_no`·`text_hash` (6건 채움 완료, 1건 미적용)

**구현 — ✅ 전부 완료 (Sprint 7 · MQ-701)**. ~~① 인증 환경변수 개명 → `LAW_API_OC`~~ (Sprint 6 · MQ-602L) ~~② 법령명 → `MST` 조회~~ ~~③ `JO` 조번호 형식 실호출 확인~~ ~~④ 응답 `조문번호`·`조문제목` 대조, 불일치 시 중단~~
확정 형식(전부 실호출 확인, 추측값 없음): `MST` 조회는 `display=100`·`search=1` + 법령명 **완전일치**, 조문 조회는 `JO` **6자리**(조4+가지2). 응답은 `조문내용+항내용+호내용+목내용` 을 **평탄화**해야 한다 — `조문내용` 이 제목 한 줄뿐인 조문이 있어 그대로 쓰면 15자짜리 제목이 "조문 원문"으로 해시된다. 상세: `analysis/law_fetch.md`
**결과: FETCHED 6 / MISMATCH 1 / FAILED 0.** `KR-CITA-ENF-31` 만 제목 불일치로 `apply_fetch` 가 파일을 손대기 전에 중단했고(사람 승인 대기), 이것이 D75 의 설계된 동작이다.

> **조문 원문을 손으로 타이핑하지 않는다.** 그 순간 "출처 있는 사실"이 아니라 "누가 적은 텍스트"가 되어 계층 1 의 존재 이유가 무너진다(`11 §8`).

**컬럼** — 제조사 · 모델명 · **제조년월** · **희망가격** · 가격협의가능 · 제품상태 · 가동여부 · 사용여부 · 수리가능여부 · 판매상태 · 카테고리1/2 · 제조국 · 물건위치 · 거래가능지역 · 수량 · 조회수 · 문의갯수

**세 갈래로 쓰인다:**

| 쓰임 | 근거 |
|---|---|
| **잔가율** | `제조년월` + `희망가격` → 경과연수별 가격 분포 역산 |
| **실사 체크리스트 그라운딩** | `제품상태`·`가동여부`·`수리가능여부` ↔ `12 §6` 9개 카테고리의 '물리적 상태' |
| **기술적 진부화** | `제조사`·`모델명` 분포로 단종·구세대 판별 (`parts.discontinued` D20 의 설비판) |

**한계 — `disclaimer` 에 반드시 남길 것:**
- `희망가격`은 **호가지 실거래가가 아니다** → A3 낙찰가로 하방 보정
- 갱신 **연 1회** → 실시간 시세 아님, 스냅샷 성격
- 취득원가 컬럼이 없어 잔가**율**을 직접 못 낸다 → 신품가 분모 필요(A4/A7)
  → 🔚 **결론이 났다: D74.** 분모를 구하는 대신 **값 원천을 목업 정률 공식으로 교체**했다.
    실측이 더 근본적인 문제를 드러냈기 때문이다 — 이 호가로 잔가율을 내면 **5종 카테고리가 전부 우상향**하고
    (`'전기전자계측'` 0-2 → 16-20 이 `0.714 → 8.381`), `카테고리2` 층화로도 사라지지 않으며,
    **동일 `모델명` 안에서 연차-가격 상관이 사실상 0**(`r = -0.17 / -0.08 / -0.04`)이다.
    호가는 연차가 아니라 **기계 규격이 지배**한다. 근거: `data/analysis/residual_curve.md §4`.
    **이 데이터는 폐기하지 않는다** — "호가로는 감가를 식별할 수 없다"는 **한계 실증**으로 보존한다.

## 4-1. 데이콘 — 확보했으나 미채택 (2026-08-12 갱신)

> ⚠️ **이 절은 원래 "채택한 적이 없다"였다. 사실이 바뀌었다** — 2026-08-12 에 **236036 기계 고장 진단
