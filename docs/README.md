# MaintQ 문서 인덱스

**3줄 요약:** MaintQ는 인버터/PLC 설비의 **생애주기 전체**를 하나의 대화로 잇는 B2B 보전 에이전트다 — 에러 진단→부품 특정→재고·견적→발주 승인, 그리고 수리 증빙→법정 조건 검사→처분 서명까지. Q 시리즈 3번째로, 주제는 도구 오케스트레이션 + **근거 기반 판단**(FinAllQ·InsuQ가 검색 깊이였다면). **AI는 근거를 조립하고, 사람이 서명한다.**

**규칙:** 설계와 다른 구현을 하려면 10_DECISIONS에 결정을 먼저 추가하고 진행한다. 새 기능 아이디어는 07_BACKLOG로 보낸다.

**범위가 넓어졌다 (D67).** `11`·`12`는 이제 본 범위다 — 당초 Phase 2로 미뤄 둔 것(D58)을 열었다. 단 **순서는 그대로** — 완료 기준 5개와 S1~S4 관통이 먼저고, 그다음 근거 계층, 그 위에 나머지가 얹힌다. 룰 카탈로그는 `data/rules/` 에 있다(테스트 19개 통과, 법령 원문은 수집 대기).

**진행 상태:** 설계 검토·정합화 완료(2026-07-18, D20~D23) → M1(데이터 준비) 진행 중. 문서 정합성 2차 점검(2026-07-23)에서 계약 구멍 5건 보완 → **D28~D32**, MVP 범위 문서화 + 발주서 추적 필드 → **D33·D34**, 프론트 구현에서 발견한 block 계약 누락 → **D35**.
매뉴얼 3종 확보 + 스파이크 SP1(표 추출) 완료 → D24~D27. `error_codes` 추출 v1 = **64건**(iG5A 23 / S100 41), 두 기종 공통 표기 코드 12종 확보(D6 "같은 코드, 다른 의미" 실증 자료 충족).
시드 `data/seed.py` 완성 — 케이스 맵 7종 자가 검증 통과. 단 `error_codes` 는 **사람 승인 게이트**에 막혀 의도적으로 비어 있다.
