### 0-1. 🔴 P28 ⓒ 의 서술이 낡았다 — "보관할 자리가 없다"는 이제 사실이 아니다

백로그 P28 ⓒ 는 *"`residual_curve` 는 테이블로 고정됐으나(D74) **그 밖의 파생 결과는 여전히
보관할 자리가 없다**"* 라고 적고 있다. 실측하면 **파생 산출물 8개가 전부 git 추적 파일**이다:

```
data/extracted/actions_absence_verification.json    data/extracted/ig5a_action_map.json
data/extracted/error_codes.json                     data/extracted/ig5a_code_map.json
data/extracted/error_codes_actions.candidate.json   data/extracted/manual_chunks.jsonl
data/extracted/extract_triage.json                  data/extracted/residual_curve.json
```

`git check-ignore` 로 대조하면 **제외되는 것이 하나도 없다.** 즉 **D60 의 요구
(*"원본은 파일(git)이 정본, DB 를 지워도 근거는 남는다"*)는 이미 100% 충족돼 있다.**

빠져 있는 것은 *보관 자리*가 아니라 **"런타임 DB 질의 소비자(조인 포함)를 가진 파생 결과의
DB 사본"** 뿐이고, **오늘 그 조건에 해당하는 것은 `residual_curve` 와 `error_codes` 둘이며
둘 다 이미 테이블이 있다** (`05_DB_SCHEMA §17`·D74·`seed.seed_residual_curve()` / `seed.error_codes_gate()`).

> 🔴 **정정 (Stage 2, §9 ②)** — 이 문단은 초안에서 *"`residual_curve` 뿐"* · *"런타임 **조인**"* 으로
> 적혀 있었고 **둘 다 틀렸다.** `error_codes` 는 런타임 질의 3종(`lookup_error_code:71` ·
> `create_po_draft:107` · **`data/hotspot_status.py:72` JOIN**) + FK 의존 1종을 갖는다.
> 게이트를 *"SQL **조인**"* 으로 좁게 쓰면 **키 조회형 `error_codes` 가 자기 게이트를 통과하지 못한다.**

나머지 7개의 소비자를 확인한 결과:

| 산출물 | 소비자 | 런타임 조인? |
|---|---|---|
| `manual_chunks.jsonl` | `mcp_server/rag.py` | ❌ 파일 직접 로드 (DB 아님) |
| `error_codes.json` | `seed.error_codes_gate()` → `error_codes` 테이블 | ✅ **이미 테이블** — 런타임 질의 3종 |

→ **지금 일반적 "분석 스냅샷 계층"을 짓는 것은 D103 이 자기 자신의 선택지 ⓒ 를 기각한
그 논리(*"DB 조회 소비자가 0 이라 YAGNI"*)를 그대로 반복하는 일이다.**

**따라서 P28 ⓒ 의 산출물은 테이블이 아니라 "승격 절차"다** — 다음 사람이 파생 결과 하나를

> ⚠ **이건 "안 하겠다"가 아니다.** P28 ⓒ 가 요구한 *"파생 결과도 테이블로 고정"* 을

### 0-3. 🔴 **새 발견** — `extract_tables()` 기본 전략이 원인·대책 표에서 **빈 표**를 낸다

백로그는 *"원인·대책 표(p125~126)는 **완전히 텍스트 추출됨**(간이판보다 우수)"* 이라고
적었다. **절반만 맞다.**

- ✅ `extract_text()` 는 글자를 전부 뽑는다 (p126 = 832자)
- ❌ **`extract_tables()` 는 빈 셀만 돌려준다** — 이 표에는 **괘선이 없어**
  (`page.lines` 의 세로선 **0개**) 기본 `lines` 전략이 표를 찾지 못한다
- ❌ 더 나쁜 것: `extract_text()` 결과는 **열이 줄 단위로 뒤섞인다**

```
 냉각 계통에 이상이 있다. 이물질이 있는지 확인합니다.     ← [원인][대책] 한 줄에 섞임
 주위 온도가 높다.  인버터 주위 온도를 40C 이하로
냉각핀 과열 유지하여 주십시오.                          ← [보호기능명] 이 문단 중간에 끼어듦
```

**줄 정규식으로 파싱하면 원인과 대책이 섞인 채로 산출물에 들어간다.** 이건 조용한 오작동이라
사람이 표를 읽을 때까지 드러나지 않는다 — `extract_error_codes.py` 의 기존 표 로직을
*"그대로 쓰면 된다"* 던 백로그의 판단은 **이 지점에서 성립하지 않는다.**

**✅ 해결책까지 실측으로 검증했다.** 괘선은 없지만 **세로 edge 는 있다** —
`page.edges` 의 `orientation=='v'` 좌표가 `99.6` · `175.3` 부근에 모여 있다. 이를
명시 경계로 주면 표가 깨끗하게 3열로 떨어진다:

```python
page.extract_tables({
    "vertical_strategy": "explicit",
    "explicit_vertical_lines": [99.6, 175.3, 330.0, 470.0],
    "horizontal_strategy": "text",
})
# → ['보호 기능', '이상 원인', '대 책']   ✅ 헤더가 정확히 3열로 분리됨
```

⚠ 좌표는 **하드코딩하지 말고 `page.edges` 에서 유도**한다 (페이지마다 미세하게 다르다).

### 0-4. 인쇄 페이지 표기 — **새 결정 불필요** (확인 후 기각한 우려)

IE5 는 쪽번호가 `13-4`·`11-8` 같은 **장(章)-상대 표기**라 `print_page_offset`(정수 뺄셈,
D26·D32·D49)에 맞지 않는 것 아닌가를 의심했으나, **iG5A 표준판도 동일한 표기 체계**다
(물리 p50 → `4-1`). 즉 **기존 매뉴얼에서 이미 성립하던 근사**이고 IE5 가 새로 만드는
문제가 아니다. → **`print_page_offset` 규약을 그대로 쓴다.**

### 0-5. 🔴 범위 — **P29 는 P11 이 아니다. model enum 을 건드리지 않는다**

`iG5A`·`S100` 쌍을 언급하는 파일이 **28개**다 (`*.py`·`*.ts`·`*.tsx`·`*.json` 기준).
CLAUDE.md 의 *"enum 확장 지점 4곳"* 은 **과소평가**다. 확인된 것만도:

```
mcp_server/tools/*.VALID_MODELS   backend/manifest.py: MODELS = ("iG5A","S100")
DB CHECK(model IN ...)            frontend/lib/citation.ts
data/raw/manifest.json            spikes/ 다수 (lookup·citation·rag·prompt_rules·sp2 …)
```

게다가 **`error_codes.json` 은 사람이 승인한 정본**이고 D99 쓰기 가드가 걸려 있다 —

→ **P29 의 산출물은 별도 후보 파일이다.** `error_codes.json` 정본을 건드리지 않고,
model enum 도 넓히지 않는다. enum 확장·정본 병합은 **P11 의 일**이고 그 앞에 **사람 검수**가 있다.

⚠ **이 경계는 뒷문으로도 넘을 수 없다.** 초안의 MQ-1401(manifest 등재)이 정확히 그
뒷문이었다 — §7-1 참조. *"enum 은 안 건드린다"* 고 적어 두고 manifest 만 손대면
`spikes/citation_render.py ⑨` 가 죽는다. **manifest 와 enum 은 분리 불가능하다.**

### 0-6. 🟡 정직하게 — **이 스프린트 산출물의 소비자는 0 이다**

## 2. 태스크 상세

### MQ-1402 — 표 추출기 (가장 위험한 태스크)

**입력**: IE5 표준판 물리 p125~126 (13장 "이상 대책 및 점검 · 고장 대책")
**출력**: `[{보호기능: str, 이상원인: [str], 대책: [str], manual_page: int}]`

구현 규칙:
1. 열 경계를 **`page.edges` 의 `orientation=='v'` 좌표에서 클러스터링해 유도**한다.
   하드코딩 금지 (§0-3).
2. `extract_tables({"vertical_strategy": "explicit", ...})` 로 3열을 얻는다.
3. **`extract_text()` 줄 파싱으로 폴백하지 말 것** — §0-3 의 열 혼입이 조용히 재발한다.
   경계를 못 찾으면 **실패로 보고**한다 (D9 — 예외 대신 status).
4. 열 개수가 3이 아니면 그 페이지는 **스킵 + 경고**. 추측 금지 (절대규칙 6 의 태도).

### MQ-1403 — 조인 (두 번째로 위험한 태스크)

원인·대책 표는 **한글 명칭**으로만 인덱싱되고 **코드가 없다.** 본문 괄호에서 얻은
`코드 ↔ 한글명` 을 붙여야 한다.

⚠ **표기 흔들림**이 실재한다 — 본문 `"인버터 냉각 핀 과열"` vs 표 `"냉각핀 과열"`.

정규화 규칙 (최소):
- 공백 전부 제거 후 비교
- 접두어 `인버터` 제거 후 재시도
- **조인 실패는 버리지 않고 `unmatched` 로 남긴다** — 사람 검수 대상이다

⛔ **유사 명칭으로 추측 매칭 금지** (절대규칙 6·D62 와 같은 태도). 매칭 실패는
*"모른다"* 로 남기고, 그것이 **몇 건인지 후보 파일에 적는다.**

### MQ-1405 — 스파이크 (검토 반영 ② — 초안에서 통째로 재설계됐다)

🔴 **문제**: `.gitignore:2` 가 `data/raw/*` 라 **IE5 PDF 는 git 에 없다**(예외는 `manifest.json`·
`INDEX.md` 둘뿐). 그런데 초안의 스파이크는 그 PDF 를 열어야 했다. 현재 **31개 스파이크 중
