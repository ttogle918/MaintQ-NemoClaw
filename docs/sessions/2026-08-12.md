## 결정과 맥락

### 판정 규칙을 **먼저** 정하고 튜닝에 들어갔다 — 이게 이 세션의 핵심

- **계기**: `eval_gap_3rd.md §4` 가 *"코드 무변경 상태에서 2·3차 사이 7문항의 판정이 뒤집혔다"* 고
  실측해 뒀다. 단일 실행 비교로는 개선과 요동을 구분할 수 없다
- **그래서**: `--repeat N` 계측을 먼저 만들고(회차마다 DB 사본·서버·포트 분리 = 독립 표본),
  **판정은 `안정 실패` → `안정 통과` 로 넘어간 칸으로만** 한다고 못 박았다
- **값을 했다**: 중간에 단일 실행이 부품 46.7 → **66.7%** 를 보였고 나는 그걸 "+20.0pt 개선" 으로
  보고했다. 3회차로 재면 **40.0 / 46.7 / 40.0** — 66.7% 는 범위 밖 이상치였다.
  **규칙을 미리 정해 두지 않았으면 요동을 성과로 발표했을 것이다**
- **대안(버림)**: 합산 비율 증감으로 판정 — B 에서 citation 이 85.2 → 92.6% 로 올랐지만
  안정 전이는 0건이고 "안정실패 → 흔들림" 이동이었다. 비율만 봤으면 B 를 채택했을 것
