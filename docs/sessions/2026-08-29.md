## 2. FinAllQ `assess-loan` 응답 `collateral_check` 3필드 → 5필드 (A2A_Q `230e492`)

추가: `insured_value` · `effective_recovery`(손해액 × 보험금액/보험가액) · `evidence[]`.
전부 optional — 없으면 키가 생략되는 하향 열화.

**MaintQ 영향: 코드 변경 불필요.** 조사 결과 MaintQ 코드에 `collateral_check` 문자열은
**한 곳도 없다**(`backend/` · `frontend/` · `mcp_server/` 전수). 화면은 처음부터 필드를
모르는 채로 그린다 — `frontend/components/chat/A2aResultCard.tsx` 의 `AssessLoanBody` 는
메타 키 3종(`status`·`request_chain_id`·`task_id`)만 빼고 **나머지를 `label: value` 로 나열**
한다(D76 — "구조를 모르므로 지어내지 않고 있는 값만 쓴다"). 즉 새 3필드는 **자동으로
표시되고**, 없으면 그냥 안 나온다. `LoanAssessmentHistory.tsx` 는 응답이 아니라 `request`
쪽만 읽으므로 무관.

**A2A_Q 의 경고("`evidence` 는 아직 약관 조항 인용이 아니라 정책 레코드 요약 — 화면에
'약관 조항 인용'으로 노출 금지", InsuQ TASK-H08 미해결)에 대해**: 현재 MaintQ 화면에는
그 위험이 없다. `AssessLoanBody` 는 중첩 객체를 `JSON.stringify` 해서 **`collateral_check`
라는 라벨 그대로** 한 줄에 찍는다 — "약관 조항 인용" 같은 해석 라벨을 붙이는 코드 경로가
없다. `evidence` 를 항목별로 렌더하는 곳은 `LookupClauseBody`(InsuQ `lookup-clause` 응답)
뿐이고 그건 다른 스킬의 다른 필드다.

**다만 이 필드를 전용 UI 로 승격하려 한다면 그때 걸린다** — 5필드를 표로 예쁘게 그리는
순간 `evidence` 에 "근거" 라벨이 붙게 되고, 그게 정확히 A2A_Q 가 경고한 상태다.
TASK-H08 이 풀리기 전까지는 **지금의 무해석 나열을 유지**한다.

**D118 과의 관계.** D118(템플릿 04 담보대출심사회신서를 MaintQ 구현 대상에서 제외)의 근거
문장은 옛 2필드 스키마(`collateral_check{coverage_amount,sufficient}`)를 인용한다. 이번
확장으로 인용이 부분적으로 낡았지만 **결론은 그대로 유효**하다 — 04 가 요구하는 것은
`LTV_THRESHOLD`·`APPRAISAL_DATE`·실제 약관 인용(`CLAUSE_QUOTE_*`)인데, 늘어난 3필드 중
어느 것도 그걸 채우지 못하고 `evidence` 는 위에서 본 대로 **아직 약관 인용이 아니다**.
D 문서는 고치지 않았다(결정이 안 바뀌었으므로).
