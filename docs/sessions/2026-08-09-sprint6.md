## 결정과 맥락 (D69~D80)

### D69 — MCP 도구 프로파일 `core|full` (기본 `core`)

- **계기**: `loop.py:262` 가 `client.list_tools()` 로 도구를 **동적 등록**한다 → 서버에 얹는 순간 14종이 프롬프트에 들어간다
- **왜 게이트가 필요한가**: 현재 지표는 부품특정 26.7%·인용률 83.3%(2차)이고 **미측정 수정 4건**이 대기 중이다.
  도구를 7종 늘린 뒤 3차를 돌리면 **"수정 효과 vs 도구 증가 효과"를 영원히 분리할 수 없다** — D56 과 같은 함정
- **기본을 `core` 로 둔 이유**: `eval/run_eval.py` 가 부모 env 를 상속하므로 기본이 `full` 이면 평가가 **아무 표시 없이** 확장 프롬프트로 돈다
- **프롬프트가 env 를 읽지 않는 이유**: 등록은 자식 프로세스, 프롬프트는 백엔드 — 두 곳이 같은 env 를 각자 해석하면 어긋난다.
  실제 `list_tools()` 결과를 넘기면 "목록에 없는 도구 사용법을 지시"하는 상태가 **구조적으로 불가능**해진다
