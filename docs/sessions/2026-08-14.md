## 결정과 맥락

### D97 — 제조사 실품번은 `parts.mfr_part_no`(nullable), `NULL` = "공개돼 있지 않음"

- **계기**: ①의 조사 결과를 어디에 둘 것인가. 문서에만 두면 **다음 사람이 같은 4축을 다시 뒤진다** —
  이건 가정이 아니라 **이미 일어난 일**이다(조달청 축이 08-12 에 기각됐는데 08-13 에 재추천됐고,
  그래서 전 세션 로그에 *"기각 근거와 미검증 가설을 분리해 남긴다"* 는 절을 따로 만들어야 했다).
- **대안과 기각 이유** (전문은 `10_DECISIONS.md D97`):
  - ① `part_no` 를 실품번으로 **교체** → **못 한다.** 값이 40종 중 **1종**뿐이라 39종에 넣을 게 없다
  - ② **있는 것만 교체(혼용)** ← **진짜 위험한 대안.** `part_no` 는 PK 이고 케이스 맵·
    `eval/testset.json`·`related_parts.seed.json`·회귀가 전부 이 문자열에 묶여 있다.
    1종만 바꾸면 **표기 체계가 반반으로 갈린 채 굳는다** — D60 이 막으려던 drift 가 식별자 층위에서 시작
  - ③ 별도 `mfr_parts` 테이블 → **결(grain)이 1:1 인데 나눈다.** D91 이 `finallq_company_id` 를
    기각한 것과 **반대 방향의 같은 오류**(그때는 결이 달라 나눴고, 여기는 같아서 안 나눈다)
  - ④ **문서로만 남김** → 위 "계기" 그대로. 기각 이유가 곧 이 컬럼의 존재 이유다
  - ⑤ `NOT NULL` + `''` 규약 → **D62 오적용.** `lien_creditor` 는 *"없음 vs 모름"* 두 사실을
    갈라야 했지만 품번은 **"공개 안 됨" 한 상태**뿐이다. 상태를 늘리면 `''` 의 뜻을 매번 되묻게 된다

### 검사 ㉖ 을 "대부분 NULL 이다"로 짜지 않은 이유

그렇게 짜면 **적재 코드가 통째로 죽어도 통과한다** — CLAUDE.md 부재검사 규칙이 금지하는 형태다.
**양성 축**(DB ≡ `MFR_PART_NO` 정본 dict) + **음성 축**(금지값 0건)을 함께 걸고,
detail 에 결론이 아니라 **두 축의 실측값**을 찍는다. **뮤턴트 6종으로 실제 실패를 확인**했고,
진짜 팬 품번 `LV0110/0150S100-FAN` 이 완제품 형명 정규식에 **오탐되지 않는 것**도 확인했다
(나중에 팬 품번을 확보했을 때 회귀가 막는 것을 방지).

## 트러블슈팅

### ㉠ 조달청 API 3종 전부 `HTTP 403` — 원인이 두 갈래로 갈렸다

- **증상**: 전 세션 계획이 *"`DATA_GO_KR_SERVICE_KEY` 는 `.env` 에 이미 있다"* 라 바로 될 줄 알았는데 전부 403
- **문제**: `403` 하나만 보면 **"활용신청 미승인"과 "키 만료·오타"를 구분할 수 없다**
- **해결**: **위조 키(`'A'*88`) 대조군**을 같은 엔드포인트에 때렸더니 **바이트 단위로 동일한 응답**
  (`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`) → 서버가 우리 키를 **알아보지도 못한다** = 활용신청 미승인.
  data.go.kr 은 **키 발급과 서비스별 활용신청이 별개**다
- **재발 방지**: `data/probe_g2b.py` 에 대조군을 **내장**했다 — 승인 후에도
  *"승인됐다"* 와 *"그냥 응답이 왔다"* 를 가른다
- **커밋**: `1ac320a`

### ㉡ 🔴 내가 "없다"를 두 번 과장했다 — 이번 세션 최대 실수

- **증상**: `part_number_sources.md` 를 **세 번** 고쳤다.
  ⓐ 초판 — ③을 전부 "미검증 2차 출처"로 묶고 **용량대 불일치를 전 품목으로** 넓게 서술
  ⓑ 1차 정정 — 사용자가 페이지를 열자 `SV-iG5A I/OPCBASSY` 가 `Part number:` 명시 ·

  **조사**에도 그대로 적용한다. ⓒ가 그 형태다(팬 축·iG5A 축이 같은 목록 안에 살아 있음)
