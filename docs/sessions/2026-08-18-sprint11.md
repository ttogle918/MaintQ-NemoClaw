## 의논 내용과 결정 맥락

### P36 승격이 `/sprint`의 명시 규칙과 충돌한 지점

`/sprint` 스킬은 "백로그(`07_BACKLOG.md`) 항목을 태스크로 승격하지 않는다"를 하지 말 것 목록에 명시한다.
직전 세션(Sprint 10)의 P37·P38은 이 규칙과 충돌하지 않았다 — Sprint 9가 규모 압축을 위해 컷한 **원래
MVP 범위 항목**이었기 때문이다. 반면 P36은 `11_ASSET_LIFECYCLE.md §10-3`이 "Sprint 7에서 v2 제외를
확정했다"고 **명시적으로** 적어 둔 순수 백로그 항목이라 성격이 다르다. 이 차이를 먼저 사용자에게
설명하고, MVP 완료 기준을 재확인한 뒤에야 D102로 의도적 편입 절차를 밟았다 — "이미 완료됐다"는 근거
없이 그냥 진행했다면 D2("완주하지 못한 MVP 위에 Phase 2를 얹지 않는다")를 위반할 뻔했다.

### D102가 `detect_law_revision`(S17)은 열지 않은 이유

같은 §10-3 절이 F5·F6 도구 3종(`track_deadlines`·`assess_risk_grade`·`detect_law_revision`)을 "셋 다
v2"로 묶어 뒀지만, `detect_law_revision`/S17 제외는 `02_SCENARIOS.md:83`이 **별도로** 확정한 결정이다.
D102의 근거(기존 룰이 이미 요구하는 저장 공간을 채운다)가 `detect_law_revision`에는 적용되지 않아 —
이 도구는 `fetch_laws.check_revisions()`가 이미 코드에 살아 있고 노출 여부만 남은 별개 문제다. 두 결정을
섞으면 "왜 하나는 열고 하나는 안 여는지"가 불투명해진다는 게 스코프를 좁힌 이유.

### 브라우저 검증을 스프린트 끝으로 미루기로 한 결정

사용자가 세션 초반 "브라우저 에이전트 활용하는건 이번 스프린트 끝나고 한꺼번에 할게. 너가 확인 가능한건
너가 확인해줘"로 명시. Sprint 11은 UI 노출이 없는 스프린트(§7에서 명시적으로 컷)라 이 지시가 사실상
스테이지 전체에 적용됐다 — DB 조회·API 직접 호출·회귀 스위트 재실행으로 자가 검증하고 사용자 확인
없이 다음 스테이지로 연속 진행했다.
