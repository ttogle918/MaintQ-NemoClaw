## 결정과 맥락

### D109 — `model` enum 을 3종(`iG5A`·`S100`·`IE5`)으로 확장, 단 정의 조회 경로만

- **계기**: 사용자가 백로그 P11 을 다음 작업으로 명시 선택. `/sprint 15` 로 pm 에이전트를 투입해
  실측했더니 **백로그 원안("enum 확장 지점 4곳")이 부정확**했다 — 실제로는 8개 코드 지점
  (`MODELS`/`VALID_MODELS` 상수) + 하드코딩 에러 메시지 여러 곳이 있었고, "DB CHECK(model IN
  ...)"는 `error_codes` 가 아니라 `equipment` 테이블에 있었으며, "프론트 타입"이라는 4번째
  지점은 애초에 존재하지 않았다(free-form string).
- **범위를 의도적으로 좁혔다**: "IE5 를 iG5A·S100 과 동급의 3번째 기종으로 완전히 편입"이
  아니라 **"정의 조회(`lookup_error_code`) 경로만 편입하고, 안전 문구·RAG·물리 설비는 명시적으로
  범위 밖에 둔다."** 근거 — `SAFETY_BASELINE["pages"]`에 IE5 를 넣으려면 안전지침 페이지의
  사람 검증이 먼저 필요한데(절대규칙 3), 그게 없다. RAG 는 IE5 매뉴얼 청킹이 아예 안 돼 있어
  `index_not_built` 을 정직하게 반환하는 게 맞다. `equipment.model` CHECK 는 IE5 실물 자산을
  시드하지 않으므로 안 건드려도 된다.
- **기각 대안**: ① 백로그 원안대로 4곳만 확장 — 지점이 더 많아 반쪽짜리 편입이 된다 ② 세이프티·
  RAG 까지 완전 동등화 — 절대규칙 3 위반 + 스코프 폭발 ③ enum 미확장 상태로 데이터만 추가 —
  sprint-14 §7-1 이 이미 "뒷문"으로 실증 기각(manifest 등재 + enum 미확장 조합은
  `citation_render ⑨` 를 크래시시킨다).

### D110 — IE5 매뉴얼도 RAG 검색 대상에 포함 (D109 ⓑ 뒤집기)

- **계기**: `/done` 으로 세션을 1차 마무리한 뒤, 사용자가 "RAG 청킹 여부 판단 가볼까?"라고
  물었다. TODO 에 "별도 스프린트 규모"라고 적어 뒀던 걸 실측으로 재확인하던 중 —
  `data/raw/manifest.json` 에 IE5 가 이미 등재돼 있어(Sprint 15) `data/chunk_manual.py` 를
  재실행하면 **자동으로 IE5 도 청킹을 시도한다**는 걸 발견했다. 실제로 돌려보니 194청크가
  코드 변경 없이 정상 생성됐고, 딱 하나 `verify()` 의 하드코딩된 2종 model assert 에서만
  죽었다(쓰기 전에 검증하는 구조라 기존 파일은 안 건드려짐 — 안전하게 확인).
- **판단**: "별도 스프린트 규모"라는 전제 자체가 틀렸다. 남은 일은 assert 한 줄 수정 +
  재생성 + 검색 품질 확인 + 새 결정 등재뿐이라 그 자리에서 바로 구현했다(사용자가 "지금 바로
  구현" 선택).
- **안전 확인을 구현 착수 전에 먼저 했다** — "RAG 는 켜면서 안전 문구는 왜 안 켜는가"에 대한
  답이 있어야 하기 때문이다. `backend/agent/prompts.py::needs_safety_block()` 이 순수 텍스트
  키워드 매칭이고 모델·데이터 출처와 무관함을 확인했고, `backend/agent/loop.py:360-382` 를
  직접 읽어 위험 절차 문장이 감지되면 `safety_page()` 가 IE5 에 대해 `None` 을 반환하고(
  `SAFETY_BASELINE` 미확장) **위험 문장 자체를 전송하지 않은 채** 방어적 거부 응답으로
  대체됨을 확인했다. 즉 이 게이트는 출력 텍스트 내용 기반이라 RAG 가 어느 매뉴얼에서 검색
  했는지와 무관하게 동작한다 — IE5 RAG 활성화가 안전 구멍을 만들지 않는다는 게 실측으로
  확정됐다.
- **기각 대안**: ① D109 그대로 유지 — 근거였던 스코프 추정이 틀렸다고 실측됐으니 유지할 이유가
  없다 ② 크래시 버그만 고치고 실제 검색 활성화는 미룬다 — 사용자가 명시적으로 "지금 바로
  구현"을 선택했다.
- **D109 를 고치지 않고 D110 을 새로 등재했다** — ⓐ(안전 미확장)·ⓒ(equipment CHECK 2종)는
  그대로 유지, ⓑ(RAG 미확장)만 좁혀 뒤집는다는 걸 명시적으로 남겨야 다음 사람이 "D109 가 RAG
  전체를 막았었나, ⓑ만 막았었나"를 헷갈리지 않는다.

  `for m in MODELS` 컴프리헨션 산물이라 **완화가 아니라 항상 참인 항등식**이 됐다.

- **해결**: `required_quoted = set(MODELS) - {"IE5"} <= baseline_quoted` 로 방향을 뒤집어
