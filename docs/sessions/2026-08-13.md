## 결정과 맥락

### D89 — 시연 공장 업종 확정 · `N = 8 → 10`
- **계기**: `N=8` 을 *"법령 원문 대조"* 하려고 별표서식 API 를 붙였는데, **근거가 두 겹으로 틀려 있었다.**
  ⓐ *"내용연수범위 6~10년의 중앙"* 이라는 유도 서술 — 별표6 은 `8년` 과 `(6년~10년)` 을 **한 칸에**
  싣는다. 중앙값 계산이 아니라 **명시값**이다. ⓑ 더 중요하게 **업종이 어긋났다** — 8년은 **제4호**
  이고 대상이 의복(14)·화학물질(20)·산업용 기계 **수리업**(34) 3종뿐인데, **제조업 중분류 15개는
  제5호(10년)** 다. **별표6 에 "제조업 기계장치" 라는 칸은 없다.**
- **대안**:
  - ① `N=8` 유지 → 근거가 무너진 값을 유지하는 것이라 기각
  - ② 업종 미정으로 두고 기본값만 10 으로 → 값은 같아지지만 *"왜 10인가"* 에 답할 수 없어 기각.
    **업종을 밝히는 것이 값보다 중요하다** (D65 와 같은 태도)
  - ③ `assets` 에 `ksic_code` 컬럼 신설 → **별표6 비고 2** 가 *"사용비율이 큰 업종을 따른다"* 고 해
    **사업장 업종 단위**로 정해진다. 자산별 컬럼은 법령 구조와 어긋나 기각
- **업종 선택**: 중분류 **`29`**(기타 기계 및 장비 제조업). 시드가 가공(2번 라인 주축·절삭유) →
  조립(1·3번) → 포장(4번) 일관 라인이고 조립라인이 4개 중 2개로 지배적이다.
  후보 `25`(금속가공제품)도 **같은 제5호**라 `N` 은 동일 — 이 선택이 곡선을 바꾸지 않는다.
- **영향 실측(A/B)**: `r` 0.0830 → 0.0670 · 3지 판정 **27조합 중 1건 뒤집힘**
  (`INV-L4-02` 랩핑기 150만원 `HOLD → REPAIR_RECOMMENDED`). 잔가가 더 남아 수리가 정당화되는 방향.
- ⛔ **`N` 이 대조를 마쳤다고 곡선이 실측이 된 것은 아니다** — `RESIDUAL_AT_LIFE_END=0.50`·`FLOOR=0.10`
  은 근거 미확보 **가정**으로 남는다.

### `law_fetch_contract` 8건 연쇄 실패
- **증상**: `KR-CITA-ENF-31` 수집 후 스위트 8건 실패
- **원인**: 검사 ⓪ 가 **"`KR-CITA-ENF-31` 은 PENDING 이어야 한다"** 를 기대값으로 박아 뒀다.
  사람 승인이라는 **정상적인 상태 변화**로 깨졌고, 그 건을 픽스처로 쓰던 ⓐ~ⓒ-7 이 연쇄 실패.
- **해결**: 스위트가 이미 `as_pending()` 헬퍼를 만들어 두고
  (*"픽스처 쪽에서 상태를 만든다 — 기대값을 정본에 맞춰 바꾸는 게 아니다"*) **한 번도 호출하지
  않고** 있었다. ⓪ 은 불변식만 보게 바꾸고(FETCHED 면 원문+해시 일치 / PENDING 이면 원문 없음),
  ⓐ 는 tmp 사본을 `as_pending()` 으로 되돌리고 시작하게 했다 → **28건 통과**
- **커밋**: `f7b963c`

### D96 — DDL 정정 (D91 supersede)
- **계기**: 내가 D91 에 쓴 DDL 스케치가 **SQLite 에서 두 군데 틀렸다**(sqlite 3.50.4 실측).
- ⓐ `CHECK (link_state = 'LINKED' OR external_ref IS NULL)` 이 `link_state=NULL` + 식별자를
  **통과**시킨다. `NULL OR FALSE = NULL` 이고 CHECK 는 FALSE 일 때만 거부한다 — **하필 "모름"
  칸에서만 새어** 목적이 절반만 달성된다 → null-safe `IS`
- ⓑ 복합 PK 의 `subject_ref` 가 NULL 이면 **동일 행 3회 INSERT 가 전부 통과**해 PK 가 무력화된다
  → `NOT NULL` + 회사 결은 `''`(D62 규약)
- ⓓ **사람 확정** — `linked_at` `DATE`→`DATETIME`(UTC). 파트너 자격증명이 발급되는 순간이고
  그 자격증명으로 **돈이 움직이는 요청**(S5)이 나간다. `decisions.signed_at`·`repair_records.signed_at`·
  `flags.raised_at` 이 이미 전부 `DATETIME` — **서명·승인 성격의 시점은 이 레포에서 이미 시각**이다

## 트러블슈팅

### ① 계획서의 `⑪-b` 판정식이 **조건부로** 죽어 있었다
- **증상**: 뮤턴트 ⓔ 를 넣었는데 `⑪-b` 가 안 잡힘. 그런데 내가 재현하니 **잡혔다.**
- **원인**: **생사가 blob 조립 방식에 좌우됐다.** `ast.walk()` 순서 + `""` 조인이면 잡고,
  `lineno` 정렬 + `"\n"` 조인이면 놓친다 — lookahead 종결자가 창(400)에 근접해 있어
  조인 문자 하나가 결과를 뒤집는다. **"정규식이 틀렸다"가 아니라 "판정식의 생사가 무관한
  구현 세부에 좌우된다"** 가 결함이다.
- **해결**: 앵커+윈도우로 쪼개고 **`anchors > 0` 을 판정에 포함**. 앵커 0 = *"쓰는 코드가 없다"* 가
  아니라 *"판정식이 죽었다"*. 교훈을 **CLAUDE.md 회귀 절 규약**으로 등재(**P30**).
- **커밋**: `e8b88aa` · `f65d30e`
