### 추출기 — 조치 컬럼을 3번 갈아엎었다

S100 `조치 사항` 컬럼은 **본문 행에서 `cells[2]` 가 항상 `None`** 이다(괘선이 닫힌 셀을
만들지 않음). 시도 순서와 결과:

1. **행 y 로 합성 크롭** → 15코드 확보하나 문장이 조각남("있는지 확인하십시오.")
   조치 문장이 같은 행 진단보다 길어 아래로 흐르는데 진단 행 y 로 자르면 끊긴다
2. **항목 셀 y 로 통째 크롭** → 더 나빠짐. 항목 셀 y 는 병합 스팬이 아니라 텍스트가
   놓인 **한 행**이라 1건씩만 잡힘
3. **컬럼을 단어로 읽어 줄→문장 재구성 후 y 로 배정** → 채택

3안에서도 스팬 경계를 중점으로 확장했더니 `Out Phase Open` 이 이웃 코드의 조치를 6건
흡수했다. **엉뚱한 에러코드에 붙은 조치는 누락보다 나쁘다** — 정비사에게 그대로 전달되는
사실 오류다. 최종적으로 **자기 스팬 안에 든 문장만 취하고 애매하면 버리는** 보수적
배정으로 갔다. 결과는 **정확하되 불완전**(S100 GFT 2/2 완전, OHT 1/4, FAN 1/3).
D1 대로 절차 본문은 RAG 담당이라 lookup 의 actions 는 보조로 충분하다고 판단.

- **T13** — `parts=['PCB-S100-CTRL-R2']` 로 대체품 특정 인정(D66 동작 확인)

다만 **같은 문항이 실행마다 다르게 흐른다** (T02 는 다른 프로브 회차에서 lookup·history
에서 종료). LLM 비결정성이라 **단일 실행 수치를 확정 실적으로 읽으면 안 된다.**

### S4 환각 의혹 — 해소

1차 평가에서 T09 가 "매뉴얼에서 코드를 찾을 수 없습니다"로 답해 환각을 의심했으나,
재현 결과 **에이전트가 `code:"fan error"` 를 통째로 넘겨 받은 정당한 `not_found`** 였다.
도구는 D25 대로 exact match 했고 에이전트도 유사 코드를 추측하지 않았다 —
**가드레일이 설계대로 동작한 사례.** 원인은 상류의 코드 토큰 추출이었고 규칙 2로 보강했다.
