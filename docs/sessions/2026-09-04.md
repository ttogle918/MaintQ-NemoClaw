## 결정과 맥락

### D124 — docx 는 템플릿을 채워 다운로드 시점에 만들고 저장하지 않는다

- **계기**: 백로그가 "경로 두 가지(`python-docx` 직접 조립 vs md+`pandoc`)" 를 남겨 뒀는데,
  착수해 보니 **그 앞에 갈림길이 하나 더** 있었다. `render_*_document()`·`render_documents()`
  는 **f-string 평문 한 덩어리**를 돌려주지 템플릿 199자리에 넣을 이름별 값 맵이 아니었다 —
  *"문안은 이미 있으니 배선만 하면 된다"* 는 절반만 맞았다.
- **대안**:
  - ① **평문을 docx 문단으로** (리팩터 0) — 기각. 문서당 표 9~13개가 전부 평문 들여쓰기로
    뭉개진다. 결재 서류의 모양이 아니고, `data/templates/README.md` 가 선언한 "양식의 정본"
    지위가 영원히 실현되지 않는다
  - ② **템플릿 없이 python-docx 직접 조립** — 기각. 배치 정본이 docx 파일과 코드로 이원화된다.
    둘이 어긋나도 아무도 모른다(D90 이 이미 겪은 실패 유형)
  - ③ **md + pandoc** — 기각. 시스템 바이너리가 필요해 배포가 한 겹 는다
- **뒷받침한 실측**: 5종 199자리 전부 **단일 `<w:t>` 런** 안에 온전해 치환이 깨끗하다.
- **핵심 ⓔ**: 신원·서명 16키(`WITHHELD_KEYS`)를 공유 계층이 **만들지 않는다.**
  만든 뒤 빼면 *규율*이지만 애초에 만들지 않으면 *구조*다 — D10 이 UPDATE 를 TEMP TRIGGER 로
  막은 것과 같은 태도.

### D125 — `get_document_facts` 는 읽기 전용이다

- **계기**: 2026-09-03 에 *"MCP 도구로 `facts` 를 수정할 수 있어야 한다"* 는 요구가 왔고
  전임 세션이 D10 근거로 거부했다. 그 확정 대안(읽기 도구 + 교정은 새 draft)의 구현이다.
- **대안**:
  - ① **MCP UPDATE 허용** — 기각. 절대규칙 1(D10) 정면 위반. 처분은 더 심하다 — `assets` 를
    고치면 `bundle_hash` 가 달라져 `sign()` 이 `EvidenceChanged` 로 막고(D84) 사용자에겐
    *"고쳤더니 결재가 안 된다"* 로 나타난다
  - ② **`withheld` 와 `unavailable` 을 하나로** — 기각. D62 위반이다. 합치면 에이전트가
    *"요청자 이름이 시스템에 없다"* 고 말하는데 **그건 거짓**이다(있고, 주지 않을 뿐이다)
  - ③ **03 도 노출** — 기각. 내부통제 판정(D119)은 `create_po_draft` 로 새 draft 를 넣어도
    안 바뀌는 **교정 경로가 없는 값**이라, 보여주면 에이전트가 그것을 두고 대화하게 된다.
    docx 다운로드는 03 포함 5종 전부 지원한다 — 제외는 이 도구 범위에만 적용
- **백로그 ㉮·㉯ 결론**: ㉮ draft 누적은 **감수**(감사 경과가 남는 게 낫다) ·
  ㉯ **템플릿 자리 그대로(필드맵)** 노출
