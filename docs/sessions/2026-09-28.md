## 트러블슈팅
### 재부팅 뒤 스택 전체가 내려가 있었다 (어제와 같음)
- **해결**: `docker start maintq_postgres` → `gateway.env` 로 `~/.local/bin/openshell-gateway` nohup → `openshell sandbox start maintq-agent` →
  MCP-HTTP 8765(`uv run --env-file .env python -m mcp_server.http_entry`, `MAINTQ_MCP_ALLOWED_HOSTS`) → 백엔드 8010 · 프론트 3000
  (`NEXT_PUBLIC_API_BASE=http://127.0.0.1:8010 npx next dev -p 3000`) → `nemoclaw maintq-agent recover` → `dashboard-url --quiet > .dash_url`.
  로그는 `~/.local/state/maintq-*.log`
### 캡션이 넘치거나 반쪽 폭으로 줄었다
- **원인**: 터미널 캡션은 높이 54px 고정 한 줄, 브라우저 캡션은 `left:50%`+`translateX(-50%)` 라 폭이 화면 절반으로 줄어 3줄로 꺾였다
- **해결**: 터미널은 `min-height`·줄바꿈 허용, 브라우저는 `width:max-content; max-width:min(1180px,94vw)`
### `pgrep -f "rec.py 5"` 가 자기 셸을 죽였다
- **원인**: 어제 기록한 `pkill -f` 함정과 같다 — 패턴이 그 명령을 실행하는 셸의 명령줄에도 맞는다
- **해결**: PID 를 확인해 `kill <pid>` 만. `awk '$3=="rec.py"'` 식 필터도 `-u` 인자 하나로 빗나갔다 — 눈으로 PID 를 보고 끈다
### 웹 콘솔 LLM 실패를 7분 동안 못 알아챘다
- **원인**: 화면 문구가 「응답 생성에 실패했습니다」 인데 녹화기는 「응답을 받지 못했습니다」·「오류」 만 셌다. 백엔드 로그는 NVIDIA `Service temporarily overloaded`
- **해결**: 감지 문자열에 「실패했습니다」 추가 → 과부하 시 즉시 재시도. 과부하는 저녁까지 간헐적(총 10회 이상 실패)
