## 트러블슈팅
### 재부팅 뒤 NemoClaw 스택 전체가 내려가 있었다
- **원인**: 게이트웨이(8080)가 systemd 가 아니라 NemoClaw 가 nohup 으로 띄운 프로세스라 재부팅에 안 살아난다
- **해결**: `gateway.env` 그대로 `~/.local/bin/openshell-gateway` nohup 기동(설정·DB 무변경) → `nemoclaw … recover/start` 는
  「Stopped」 에 묶여 타임아웃 → **`openshell sandbox start maintq-agent`** 로 Ready → 대시보드 포워드는 그 뒤 `nemoclaw maintq-agent recover`
### 샌드박스 env 에 `NVIDIA_API_KEY` 가 있다
- **원인**: 값이 `openshell:resolve:…` 게이트웨이 참조(placeholder)다. 실키(`nvapi-`) 0건 — 결함 아님, 장면 7 증거로 씀
### 웹 콘솔 발주 초안 턴에 「근거 문서를 확인하지 못해…」 가 끼어든다
- **원인**: 그 턴엔 매뉴얼 조회가 없는데 부품·수량 문장이 위험 키워드에 걸려 `loop.py` 안전 가드가 설계대로 치환. 마감 직전이라 미수정
### Playwright 녹화
- 크로미움 의존 라이브러리 없음(sudo 불가) → `apt-get download libnspr4 libnss3 libasound2t64` 를 로컬에 풀고 `LD_LIBRARY_PATH`.
  OpenClaw 대시보드 CSP 가 `wait_for_function` 문자열 eval 을 막음 → `bypass_csp=True`. NVIDIA 과부하 → 실패 감지 후 재녹화 루프
- `pkill -f "python rec.py"` 가 자기 셸 명령줄에 매치돼 셸이 죽었다(day2 §9 와 같은 함정) — **PID 로만 끈다**
