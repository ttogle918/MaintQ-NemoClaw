위반 4건이 드러났다. 세 선택지(지금 함께 고치기 / 글롭 확장만 되돌리기 / 둘 다 미해결로 두기)를 사용자에게

### `RepairDetail.tsx` 서명/반려 직후 상세 패널이 새로고침해야만 갱신 (브라우저 실사용 발견)
- **증상**: 서명·반려 버튼을 눌러도 알림 토스트와 좌측 큐 목록 배지는 즉시 바뀌는데, **열려 있는 상세
  패널 자체**(상태 배지·서명 해시·컨트롤 노출 여부)는 그대로 남아 있다가 새로고침해야 바뀜
- **원인**: `RepairDetail` 이 자기 소유 `repair` state 를 `repairId` 로만 재조회(`useEffect`)하는데,
  `doSign`/`doReject` 는 성공 시 부모에게만 `onUpdated(updated)` 를 알리고 **자기 자신의 state 는 안 바꿈**
  — `repairId` 는 서명 전후로 안 바뀌므로 `useEffect` 가 재발화하지 않음
- **해결**: `RepairControls` 에 전달하는 `onUpdated` 콜백에서 `setRepair(updated)` 를 먼저 호출한 뒤 부모
  콜백을 부르도록 수정
- **커밋**: `95e09a8`
