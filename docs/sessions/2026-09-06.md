## 결정과 맥락

### D135 — `part` 실패를 «오특정»과 «미특정»으로 나눈다

- **계기**: 두 모델의 `part` 합계가 **45.6% vs 51.0%** 로 *"차이 없음"* 이었다. 그런데
  `_identified_part()` 로 **실제 선택**을 세어 보니 정반대였다 —
  오특정 **120b 32/90(35.6%) · 20b 9/100(9.0%)**, 미특정 **120b 17/90 · 20b 40/100**.
  **120b 는 틀린 답을 확신하고, 20b 는 답을 안 낸다.** 합계가 두 축을 상쇄해 지운다.
- **위험도가 다르다**: 오특정은 정비사가 **엉뚱한 부품을 발주**하게 만들고(비용·설비 정지),
  미특정은 답을 못 받는 것이다. 같은 `FAIL` 로 접으면 **더 위험한 쪽이 좋아 보인다** —
  이번에 실제로 120b 가 그렇게 보였다.
- **대안 기각**:
  - *가중 페널티* — 가중치를 정할 근거가 없고, 하나의 숫자로 접으면 어느 축을 고쳤는지
    사후에 알 수 없다. D66 이 *"완화는 오판"* 으로 거부한 것과 같은 계열.
  - *모델을 시나리오 분기별로 고른다* — **이 세션에서 내렸다가 철회한 해석**(§철회 ③).
- **구현**: 판정은 `score.part_failure_kind()` 가 **단독 소유**한다 — `_judge_part` 와 같은
  근거(`_identified_part`)를 쓴다. 따로 재구현하면 리포트의 `passed` 와 조용히 어긋난다.
  **렌더(`_part_failure_lines`)도 계약에 넣었다** — 집계만 하고 인쇄하지 않으면 같은 실수가
  반복된다. 뮤턴트로 실증: 판정을 `return PART_WRONG` 으로 망가뜨리면 3건 FAIL,
  **렌더만 지우면 ⑫-m 하나만** FAIL 한다(그 검사가 제 몫을 한다는 뜻).

### 노이즈 바닥 — `gpt-oss:20b` 5문항 × 20회차

`part` **안정통과 0 · 안정실패 0 · 흔들림 5** — 다섯 문항이 전부 흔들렸다.
`p≈0.5` 인 세 문항의 95% 신뢰구간 폭이 **40pt**. 직전 세션이 예고한 *"30회 이상"* 은
낙관적이었다 — **20회차로도 0.3 과 0.7 을 못 가른다.**

같은 조건 10회차 배치 둘이 `citation` 에서 **12pt** 어긋났다(92% vs 80%).
10회차 수치를 인용하면 **없는 회귀를 보고하게 된다.**

## 트러블슈팅

### ㉠ `[WinError 10014]` — 회차 시작에서 죽는다

- **증상**: `socket.socketpair()` → `lsock.listen()` 이 WSAEFAULT. 배치가 통째로 죽는다.
  처음엔 **3회차에서 결정적으로 죽는 구조적 결함**으로 보였다(배치 1·2가 둘 다 3회차).
- **배제한 것** (10초 간격 계측): 서버 프로세스 `4→8→4` **기준선 복귀** · 핸들
  `~920↔~1840` **복귀** · 러너 RSS 4회차에 79→168MB. **누수 없음**,
  `_shutdown_server` 의 `taskkill /T /F` 정상. 조사 중 발견한 고아 uvicorn 트리는
  **내가 큐를 회차 도중 강제 종료해서** 생긴 것이었다.
- **원인**: 머신 여유 메모리 압박(실행 중 **1,606~3,080MB / 32,328MB**,
  `vmmemWSL` 이 **7,850MB** — 다른 프로젝트 컨테이너 12개). 평가가 겹치면 회차마다
  uvicorn(~130MB)+MCP(~88MB)가 더 얹힌다.
- **해결**: 근본 해소는 못 했다(환경). 대신 **손실을 0 으로 만들었다** — §㉡.
  실패는 **항상 회차 시작 지점**이고 문항 실행 중 죽은 적은 없다.

### ㉡ 죽은 배치를 traces 로 되살렸다 (LLM 호출 0회)

- **계기**: 120b 배치 5개가 전부 죽어 리포트(`.json`)가 하나도 안 남았다.
- **핵심**: `score.py` 의 판정은 전부 `score_session(events, expected)` —
  **`response_text` 를 쓰지 않으므로 저장된 `.rN.traces.jsonl` 만으로 완전 재채점된다.**
  120b 표본 18회차 중 **14회차가 죽은 배치에서 나왔다.**
- **순서 규칙 준수** (`memo/eval-harness-debug §3 ②`): 되살리기 **전에** 살아 있는
  리포트의 문항별 판정 **60칸을 재채점으로 대조해 불일치 0** 을 확인했다. 폴백 혼입 0건.
- **그래서**: 리포트가 아니라 **`.rN.traces.jsonl` 이 진짜 원본**이다.

### ㉢ `git checkout master` 가 auto mode 분류기에 막혔다

- **증상**: 브랜치 전환이 차단돼 FF 머지 불가. `git checkout -b`(새 브랜치)는 통과한다.
- **해결**: 우회하지 않고 사용자에게 알려 직접 실행받았다. 두 번째 머지는 통과했다.
