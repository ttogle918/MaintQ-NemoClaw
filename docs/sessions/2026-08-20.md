## 결정과 맥락

### D106 — 파생 결과의 DB 승격은 "런타임 DB 질의 소비자(조인 포함)가 생겼을 때"만

- **계기**: P28 ⓒ 를 착수하려고 실측했더니 **그 항목의 전제가 틀려 있었다.** *"파생 결과는 보관할
  자리가 없다"* 고 적혀 있었으나 `data/extracted/` 산출물은 **전부 git 추적**이라 D60 요구
  (*"DB 를 지워도 근거는 남는다"*)가 **이미 100% 충족**돼 있었다.
- **대안**: ⓐ 모든 파생 결과를 선제적으로 테이블화 → **D103 이 자기 선택지 ⓒ 를 기각한 논리
  (*"소비자 0 이라 YAGNI, 사본은 drift 축만 늘린다"*)의 반복**이라 기각 ⓑ 규약 없이 그때그때 판단
  → `residual_curve` 선례가 묻히고 **다음 사람이 같은 논의를 처음부터 다시 한다**(P28 ⓒ 가 낡은
  서술로 남아 있던 것이 그 증거).
- **핵심은 4단계 중 ④(drift 자가검증)** — 사본을 만든 순간 파일↔DB 가 어긋날 축이 생기고,
  그걸 잡는 검사가 없으면 **승격은 개선이 아니라 부채**다.

### D107 — 괘선 없는 표는 `page.edges` 유도 명시 경계로 추출하고 폴백을 두지 않는다

- **계기**: IE5 원인·대책 표(p125~126) 실측. 백로그 P29 는 *"표는 완전히 텍스트 추출됨 → 기존 표
  로직 그대로"* 라고 적었으나 **절반만 맞았다** — 괘선이 없어(`page.lines` 세로선 0개)
  `extract_tables()` 가 **빈 셀만** 내고, `extract_text()` 는 **열을 줄 단위로 뒤섞는다.**
- **대안 기각의 진짜 이유는 실패 방식**이다 — 줄 파싱은 **틀린 값을 성공처럼 반환**한다. 원인과
  대책이 섞인 채 산출물에 들어가면 사람이 표를 직접 읽을 때까지 드러나지 않는다. **폴백을 두면
  경계 유도가 회귀했을 때 조용히 그 경로로 내려간다** — 그래서 ⓓ(폴백 없음)를 결정에 넣었다.

### P41 ③ — 부서 ⊥ 역할 (사용자 결정)

- `users.role` = **권한**, `users.department` = **소속**. `require()` 는 role 만 본다 —
  재무부 소속이어도 role 이 없으면 승인 못 한다.
- **`X-Dept` 헤더 금지** — 참칭 가능. 서버가 `users` 테이블에서 조회해 주입(D52 태도).
- **채택 ⓐ**(부서로 **필터링만**, 권한 동일). 대가를 알고 수용 — 정비팀장과 재무부 담당자가
  서로의 건을 승인할 수 있다. 나중에 P9 에서 `role` 을 늘리면 ⓑ 로 가고, **그때 판정에 들어가는
  것은 `department` 가 아니라 `role`** 이라 원칙이 깨지지 않는다.
- **첫 적용 대상은 발주 승인이 아니라 지출 분류 화면** — `classify_expenditure`(자본적/수익적)는
  회계 판단이라 원래 재무 소관이고, 새 상태 머신·전이가 없다.

### 계획 단계에서 **삭제한 태스크** — MQ-1401 (manifest 등재)

IE5 를 `manifest.json` 에 `role: "primary"` 로 넣으면 `spikes/citation_render.py ⑨` 가
`print_page_offset("IE5")` → `manual_entry` → `validate_model` 에서 **FAIL 이 아니라 예외로 죽는다.**
피하려면 model enum 을 넓혀야 하는데 **그것이 §0-5 가 금지한 변경**이다. → manifest 와 enum 은
분리 불가능하므로 **P11 로 이관**. `citation_render` 18건 유지가 사후 증거다.
