D68 — 실측이 바꾼 것

2026-08-07 · 확장 범위의 대상 재정의

중진공 CSV를 실제로 열어 본 결과가 설계 공백을 하나 드러냈고, 그게 D68이 됐습니다. 데이터가 없어서 생긴 문제가 아니라 데이터를 보니 드러난 문제입니다.

발견

대상이 어긋나 있었다

문제

중고설비 매물 16,011건 중 인버터는 4건, 공작기계는 7,048건. 이 시장은 완제품 설비지 부품이 아닙니다. 그런데 확장 범위(S9·S10·S18)의 대상이 equipment_id = 인버터였습니다.

11 §1이 처분 서사의 근거로 든 "수명 20~30년 · 신품 납기 수개월~1년 · 급하면 중고가 유일 대안"은 공작기계 특성이지 인버터가 아닙니다. 근거와 대상이 처음부터 어긋나 있었습니다.

해결

실마리는 이미 데이터 안에 있었다

D68 확정

equipment.location에 호스트가 이미 문자열로 있었습니다 — 반송 컨베이어 · 랩핑기 · 집진기 · 리프터 · 절삭유 펌프 · 주축 · 배기팬. 지어내는 게 아니라 있던 정보를 승격하는 것입니다.

assets 신설 + equipment.asset_id FK. 확장 6종은 asset_id, 기존 6종은 equipment_id 그대로 — MCP 도구 계약 무변경.

제약 3가지를 함께 못 박았습니다. ⓐ 기존 6종의 도구 계약·equipment_id 불변 (D67 "범위는 넓히되 순서는 지킨다"와 같은 태도) ⓑ S3 반복고장 판정은 인버터 단위 유지 — 에러코드가 인버터의 것이므로. 12 §1의 "감점 신호 재사용"은 asset_id로 집계하는 것이지 판정 기준 변경이 아닙니다 ⓒ assets는 F2~F4 착수 시점에 생성 — F1(근거 계층)은 자산 구조와 무관하므로 D68이 F1을 막지 않습니다
보너스 — 확인불가 함정. CSV의 제조년월 "결측률"은 0%지만, 결측 대신 확인불가 문자열이 채워져 있습니다. 결측률을 그대로 믿고 5,911 대신 16,011을 분모로 쓰면 잔가곡선이 통째로 틀어집니다. 유효 표본은 연도 5,911 · 연도+가격 교집합 5,396(33.7%)입니다.
