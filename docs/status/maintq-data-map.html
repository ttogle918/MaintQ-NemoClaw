데이터 3분류 — 이 문서 전체에서 같은 색을 씁니다

"실제"와 "생성"을 구분하는 이유는 신뢰도가 다르기 때문입니다. 실제 데이터에 근거한 판정은 인용할 수 있지만, 목업에 근거한 수치는 반드시 추정치임을 고지해야 합니다(D65).

실제 데이터외부 원천에서 받은 것 — LS 공식 매뉴얼, 공공데이터, 법령 원문. 근거로 인용 가능
생성한 데이터우리가 만든 것 — seed.py 목업, 수기 매핑, 직접 작성한 해석 룰. 고지 필요
앞으로 만들 데이터아직 없음 — 확장 기능이 요구하는 테이블·컬럼. 일부는 실제 데이터에서 파생

파일이 정본, DB는 질의용 사본입니다(D60). IROS 291행을 받고 가장 먼저 물은 것이 "DB에 넣을까, 벡터 DB에 넣을까"였는데 둘 다 지금은 아닙니다 — 소비처(기능 12의 residual_risk)가 아직 이 통계를 읽지 않기 때문입니다. 특히 벡터 DB는 이 데이터에 원리적으로 안 맞습니다 — 연도별 집계 수치를 의미 유사도로 찾을 일이 없고, 근사 검색은 "2024년 3분기 108건"을 "2023년 3분기"로 바꿔 놓을 수 있습니다. 근거로 인용할 숫자에는 결정론적 조회만 씁니다(D59와 같은 성질).
실데이터가 늘었다고 신뢰도가 자동으로 오르지 않습니다. 이번에 늘어난 것 중 실제 데이터는 법령 조문 6개뿐이고, assets·repair_records·residual_curve는 전부 우리가 만든 것입니다. 특히 residual_curve는 실데이터로 만들려다 실패해서 목업으로 되돌아온 항목입니다 — 그 실패를 지우지 않고 residual_curve.md §4에 남긴 이유는, 다음에 같은 데이터를 보고 같은 기대를 하지 않기 위해서입니다.
