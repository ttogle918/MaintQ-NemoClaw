# memo — 작업 메모

**결정(`10_DECISIONS.md`)도 아니고 세션 로그(`sessions/`)도 아닌 것**을 둔다.

| | 성격 | 어디에 |
|---|---|---|
| *"왜 이렇게 하기로 했나"* | 대안·기각 사유가 있는 **결정** | `10_DECISIONS.md` |
| *"그날 무슨 일이 있었나"* | 시간순 **작업 기록** | `sessions/` |
| ***"재 보니 이렇더라"*** | **실측값·관측·시도한 것** | **여기** |

여기 있는 문서는 **작업 중 다시 열어 보게 되는 실측 자료**다. 예를 들어
*"이 API 키로 어떤 모델을 쓸 수 있더라?"* 는 결정도 아니고 그날의 사건도 아니지만,
매번 다시 재기엔 비싸다.

## 규칙

- **실측값을 적는다.** 인상이 아니라 숫자와 날짜. 잰 방법(커맨드)도 함께 남긴다 —
  값은 낡아도 **재는 방법은 오래 간다**.
- **낡을 수 있음을 전제한다.** 각 문서 머리에 측정 시점을 박는다. 외부 서비스 카탈로그처럼
  통제 밖의 것은 특히 그렇다(실제로 이 프로젝트는 모델이 **EOL 되면서** 평가가 통째로 무효가 된 적이 있다).
- **틀렸던 것도 남긴다.** 특히 *"확실하다고 믿었다가 뒤집힌 것"* — 같은 함정을 다시 밟지 않으려면
  결론뿐 아니라 **어쩌다 틀렸는지**가 필요하다.
- 여기 적힌 것이 설계를 바꾸는 근거가 되면 **결정으로 승격**해 `10_DECISIONS.md` 에 올린다.
