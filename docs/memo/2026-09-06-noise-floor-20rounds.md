## 5. 모델 비교 — 합계는 같고 문항별로는 정반대다

### 120b 표본을 어떻게 만들었나 (LLM 호출 0회)

120b 배치 3개는 중도에 죽었지만(§6) **죽기 전에 완주한 회차의 traces 는 남아 있다.**
`score.py` 의 판정은 전부 `score_session(events, expected)` — `response_text` 를 쓰지
않으므로 **저장된 traces 만으로 완전 재채점된다.** 그래서 버려졌던 6회차를 되살렸다:
`000653` r1·r2 + `000955` r1·r2·r3 + `001526` r1.

원인 조사용 실행(`probe/20260906-001619`, 120b 4회차 리포트)과 합쳐 **120b 10회차**.

> 🔴 **순서 규칙을 지켰다** (memo/eval-harness-debug §3 ②): 되살리기 **전에**
> probe 리포트의 문항별 판정 **60칸을 재채점으로 대조해 불일치 0** 을 확인했다.
> 재현 못 하는 하네스의 결과는 무의미하다. 폴백 혼입도 0건(모델이 섞이지 않았다).

### `part` — 합계가 숨긴 것

| 문항 | 분기 | `gpt-oss:120b` (n=10) | `gpt-oss:20b` (n=20) |
|---|---|---|---|
| T05 | s1_pipeline | **0/10 0%** [0%, 28%] | 10/20 50% [30%, 70%] |
| T06 | s1_pipeline | **0/10 0%** [0%, 28%] | 9/20 45% [26%, 66%] |
| T13 | s2_alternative | **7/10 70%** [40%, 89%] | 3/20 15% [5%, 36%] |
| T14 | s2_alternative | 8/10 80% [49%, 94%] | 10/20 50% [30%, 70%] |
| T15 | s2_alternative | 10/10 100% [72%, 100%] | 19/20 95% [76%, 99%] |
| **합계** | | **25/50 = 50%** | **51/100 = 51%** |

**합계는 50% vs 51% 로 구분이 안 되는데, 문항별로는 역할이 완전히 뒤집힌다.**
`s1_pipeline` 두 문항은 **20b 가 이기고**(T05·T06 은 신뢰구간이 겹치지도 않는다),
`s2_alternative` 의 T13 은 **120b 가 이긴다**(70% vs 15%, 역시 겹치지 않는다).

> 직전 세션의 `20b 80%` vs `120b 60%` 는 **"노이즈였다"로 닫으면 안 된다.**
> 20문항의 s1/s2 **구성비**가 만든 값일 수 있다 — 두 모델이 서로 다른 분기에서 이기므로
> 문항 구성이 순위를 정한다. 모델 순위를 매기려면 **분기별로 따로** 재야 한다.

### `citation`·`safety` — 여기선 120b 가 낫다

| | 120b (n=50) | 20b (n=100) |
|---|---|---|
| citation | **100%** (50/50) | 86% |
| safety | **94%** (47/50) | 77% |

### T15 (§4 보강)

**두 모델에서 함께 높다** — 120b `10/10`, 20b `19/20`. D134 효과가 모델 특성이 아니라는
근거가 된다.

⚠ **회차가 적을 때의 `stable_fail` 은 여전히 믿을 것이 못 된다.** probe 4회차만 봤을 때
T05·T06 이 `0/4 안정실패`로 찍혔는데, **같은 문항을 20b 는 10/20·9/20 으로 낸다.**
120b 의 `0/10` 은 n=10 이라 구간 상한이 28% 로 훨씬 단단하지만, **모델을 바꾸면 뒤집히는
분류**라는 점은 같다 — "이 문항은 어렵다"가 아니라 "이 모델이 이 문항에서 진다"이다.

## 6. `[WinError 10014]` — 코드 결함이 아니라 자원 경합

배치 6개 중 4개가 회차 도중 죽었다. 전부 같은 예외다:

```
File "eval/run_eval.py", line 1533, in _run_round
    if not asyncio.run(_wait_ready(base_url)):
  ... socket.socketpair() → lsock.listen()
OSError: [WinError 10014] 잘못된 포인터 주소
```

처음엔 **3회차에서 결정적으로 죽는 구조적 결함**으로 보였다(배치 1·2가 둘 다 정확히
3회차에서 죽었다). **틀린 해석이었다.**

### 계측으로 배제한 것

10초 간격으로 회차 내내 잰 값(`freeMB` · 서버 프로세스 수 · 러너 RSS · 핸들 수):

| 검사 | 실측 | 판정 |
|---|---|---|
| 서버 프로세스 누적 | 회차마다 `4 → 8 → 4` **기준선 복귀** | 누수 없음 |
| 핸들 누적 | `~920 ↔ ~1840` **기준선 복귀** | 누수 없음 |
| 러너 RSS | 4회차에 걸쳐 79 → 168MB | 폭주 없음 |
| 머신 여유 메모리 | **1,606 ~ 3,080MB / 32,328MB** | 압박 |

`_shutdown_server` 의 `taskkill /T /F` 는 정상 동작한다. 조사 중 발견한 고아 uvicorn
트리는 **내가 큐를 회차 도중 강제 종료해서 생긴 것**이었지 정상 경로의 누수가 아니었다.

### 결정적 증거 — 시간대와 성패가 정확히 대응한다

| 시각 | 동시 실행 | 결과 |
|---|---|---|
| 09:06 ~ 09:27 | 큐 + 내가 띄운 재현 실행 **2개** | 배치 4개 **전부 실패** |
| 09:27 ~ 10:28 | 큐 **단독** | 배치 2개 **10/10 완주** |

**`--repeat 10` 은 경합만 없으면 멀쩡히 돈다.** 연속 2배치 20회차에 `STREAM_ERROR 0`.
이 머신의 여유 메모리를 먹는 것은 `vmmemWSL` **7,850MB**(다른 프로젝트 컨테이너 12개)다.

### 그래서 규칙

- **평가 실행 중에 다른 평가를 띄우지 않는다.** 회차마다 uvicorn(~130MB)+MCP(~88MB)를
  새로 띄우므로 두 실행이 겹치면 여유가 바닥난다.
- 실패해도 **배치 단위로만 잃는다** — 한 회차 실패가 `--repeat 10` 전체를 죽이므로
  배치를 잘게 쪼갤수록 손실이 작다. 이번에 그렇게 8회차를 두 번 잃었다.
- CLAUDE.md 가 스파이크에 대해 적어 둔 *"단독 재실행하면 통과한다"* 와 **같은 부류**다.

## 7. 재는 방법

```bash
# 5문항 부분집합 (T05·T06·T13·T14·T15) 을 testset 으로 만들어
uv run python eval/run_eval.py --testset <부분집합>.json --repeat 10 --yes \
    --out-dir eval/results/noise30
# 모델은 env 로 고른다 (.env 의 MAINTQ_LLM_MODEL 을 OS env 가 이긴다)
MAINTQ_LLM_MODEL=gpt-oss:20b  uv run python eval/run_eval.py ...
```

**배치가 죽어도 완주한 회차는 버리지 않는다.** 리포트(`.json`)는 안 남아도
회차별 `.rN.traces.jsonl` 은 남아 있고, `score.score_session(events, expected)` 가
`events` 만으로 `part`·`citation`·`safety` 를 전부 판정하므로 **LLM 호출 0회로 재채점**된다
(`session_id` 는 `EVAL-<문항id>`). 이번에 그렇게 120b 6회차를 되살렸다 — 되살리기 **전에**
살아 있는 리포트로 재현성부터 단언할 것(§5).

배치를 이어붙여 흔들림을 다시 낼 때는 **판정 정의를 재구현하지 말 것** —
`eval/run_eval.py` 의 `item_outcomes()` · `flip_analysis()` 정본을 그대로 부른다.
재구현하면 리포트와 표가 조용히 갈라진다. (병합 스크립트는 일회용이라 레포에 두지 않았다.
`items[]` 레코드에 `events` 가 없으므로 `excluded_stream=0` · `excluded_failed=0` ·
캐시 히트 0 을 리포트에서 확인한 뒤 `events=[]` · `llm_stream_failed=False` 로 채운다.)
