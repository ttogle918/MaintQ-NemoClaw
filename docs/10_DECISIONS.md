# 의사결정록 (Decision Log)

설계 과정에서 내린 주요 결정과 이유. 면접에서 "왜 이렇게 했나요?"에 대한 답변 원본.

| # | 결정 | 대안 | 채택 이유 |
|---|------|------|----------|
| D1 | 에러코드 조회를 **룩업/RAG 이원화** | RAG 단일 | 코드 정의는 exact match 문제. RAG만 쓰면 오히려 부정확. "문제 성격 따라 도구를 나눴다"가 프로젝트 핵심 스토리 |
| D2 | 확정 기능: **반복 고장 감지 + 안전 가드레일** | 사진 진단, 긴급도 공급사 추천 등 | 데이터 준비 부담 대비 차별화 효과. 나머지는 백로그(07) |
| D3 | **B2B 사내 도구** 포지셔닝 | B2C 가전 진단 | PLC/인버터 사용 주체가 공장. 승인 워크플로우 자체가 기업 프로세스. 채용 수요도 B2B 에이전트에 집중 |
| D4 | 페르소나 2명 분리 (정비사/팀장) | 단일 사용자 | 진단자와 발주 승인자가 다른 게 현장 실제. human-in-the-loop이 안전장치가 아니라 조직 프로세스 반영이 됨 |
| D5 | **실패 시나리오 S4** 추가 | 성공 시나리오만 | 오케스트레이션 프로젝트에서 실패 처리는 본체. 미지 코드에 추측하지 않는 에이전트 = 환각 방지 증명 |
| D6 | 기종 **2개** (iG5A + S100) | 1개 / 3개+ | 1개면 "같은 코드, 다른 의미" 필터링 증명 불가. 3개+는 M1 데이터 준비 폭발. 2개가 최소 증명 단위 |
| D7 | CMMS 대비 포지셔닝: **"기록과 문서 사이의 판단 업무"** | CMMS 경쟁 구도 | CMMS는 기록, 매뉴얼은 정적 문서. 진단(판단)→조달(액션) 연결이 빈 자리. + "신입도 고참처럼" 암묵지 프레임 |
| D8 | `get_lead_time`을 `get_supplier_quotes`로 흡수 (7→6개) | 별도 유지 | 리드타임·단가·MOQ는 항상 세트로 필요. 호출 2회→1회 |
| D9 | 도구 실패를 예외가 아닌 **status 필드로 반환** | 예외 발생 | 에이전트가 not_found/empty를 보고 S2·S4 분기 가능해야 함 |
| D10 | 쓰기 도구는 `create_po_draft` 하나, **draft 생성만** 가능 | 도구에 승인 권한 부여 | human-in-the-loop을 프롬프트가 아닌 도구 권한 수준에서 강제. 도구에 UPDATE 권한 자체가 없음 |
| D11 | DB 테이블 6→**8개** (`error_codes`, `equipment` 추가) | — | 룩업 도구의 원천 테이블과 이력의 FK 대상이 누락돼 있었음 |
| D12 | `error_codes.related_parts` 컬럼 | 부품 특정을 LLM 추측에 위임 | 진단→부품 특정을 데이터 기반으로. 없으면 특정 정확률 90% 달성 불가 |
| D13 | `(model, code)` 복합키 | code 단일키 | "같은 코드, 다른 의미"를 스키마 수준에서 구현 |
| D14 | 응답과 trace를 **같은 SSE 채널, 다른 이벤트 타입**으로 | 별도 폴링 API | 채팅과 trace 패널이 스트림 하나로 자연 동기화 |
| D15 | MCP 서버·백엔드 **프로세스 분리** | 단일 프로세스 | 목업 DB→실제 ERP 교체 시 MCP 서버만 갈아끼우는 구조 = 실전 연동 가능성 어필 |
| D16 | 데이터 소싱: 데이콘 **패스**, LS 공식 매뉴얼 + AI허브 보조 | 공개 데이터셋 중심 | 데이콘/AI허브는 센서·이미지 위주. 핵심 데이터(에러코드·부품)는 매뉴얼+목업이 정답. AI허브 고장 예지 데이터는 이력 시드 분포 참고, 표 정보 QA 데이터는 표 파싱 평가 방법론 참고 |
| D17 | 프로젝트명 **MaintQ** | FacQ, PlantQ, DiagQ | 타겟(설비보전팀)과 이름이 일치, Q 시리즈(FinAllQ·InsuQ) 규칙 유지, maintenance 키워드 검색성 |
| D18 | 승인은 채팅 밖 **승인 큐 화면**에서 | 채팅 말풍선 내 버튼 | 채팅에선 결재가 흘러가버림. 실제 결재 동선과 일치 + 근거 요약 카드로 대화 안 읽고 판단 가능 |
| D19 | 매뉴얼 원본은 **manifest 기반 버전 관리**, 추출은 100% 코드(멱등 재실행) | 실시간 링크 크롤링 / Claude 수작업 추출 | 매뉴얼 개정은 연 단위 이벤트라 실시간 최신화는 과설계. 다운로드 URL도 동적이라 직링크 불안정. 대신 raw는 불변+출처·해시 추적(manifest.json), 파이프라인은 재실행 가능 스크립트로 분리. 자동 워처는 백로그 P13 |
| D20 | 도구 출력 계약 보강 — `lookup_error_code` 출력에 `related_parts`, `search_inventory` 출력에 `discontinued` 포함 | 계약 유지(에이전트가 추론) | 05·S1·D12가 전제하는 진단→부품 연결 고리가 도구 계약에 없었음. 없으면 부품 특정이 LLM 추측으로 회귀(D12 위배), S2의 단종 분기도 판단 근거 없음. 설계 검토(2026-07-18)에서 발견된 계약 누락 수정 |
| D21 | trace를 SQLite **traces 테이블**로 영속화 + `po_drafts.session_id` 컬럼 추가 (테이블 8→**9종**) | 세션별 JSONL 파일 | GET /trace, 화면 B의 trace 링크, scenario-smoke의 시퀀스 판정이 전부 저장된 trace를 전제. 목업 DB와 같은 SQLite에 두면 발주↔trace 조인 조회가 일관되고 별도 파일 관리가 없음 |
| D22 | SSE 4번째 이벤트 **`block`** 추가 — 안전 경고·발주 카드·인용 등 구조화 블록 전달 (D14를 3종→**4종**으로 개정) | 최종 `done` 이벤트에 구조화 결과 몰아넣기 | 안전 경고는 **스트리밍 중간 삽입**이 필요 — done 방식이면 위험 절차 서술이 먼저 흘러가고 경고가 뒤늦게 도착함. safety-guardrail 스킬의 "구조화 필드 분리" 요구와 D14가 충돌하던 것을 해소 |
| D23 | 목업 신원은 **`X-User` 헤더**로 전달, `requested_by`/`decided_by`는 백엔드가 **서버 측에서 주입** | create_po_draft의 도구 파라미터로 전달 | **도구 파라미터가 아닌 서버 주입 = LLM이 신원을 위조할 경로 자체를 차단.** 도구 스키마에 신원 필드가 없으므로 프롬프트 조작으로도 타인 명의 발주 요청이 불가능 |
| D24 | 추출 전략: **pdfplumber `extract_text()` 행 단위 규칙 파싱** (extract_tables는 보조) | extract_tables 단독 / camelot / 비전 모델 | SP1 실측: 3종 모두 텍스트 레이어 존재(스캔본 아님), extract_tables는 병합 셀·다단에서 열 정합 붕괴 빈번. S100은 키패드 코드가 텍스트로 존재, iG5A는 통신 챕터 비트명(20종)↔한글명 매핑(사람 검수)으로 우회. 비전 모델은 과설계 |
| D25 | 코드 정규화: 저장은 **대문자 canonical**(`code`), `display_code`에 키패드 원표기 보존, lookup은 **case-insensitive** 매칭 | 원표기 그대로 저장 | 같은 코드가 소스별 표기 상이 — S100 키패드는 소문자(oct), iG5A 비트명은 대문자(OCT), 사용자 입력은 혼재(OHt). 통일 없으면 정상 코드가 not_found로 새어 S4 오탐 |
| D26 | 페이지 인용은 **PDF 물리 페이지** 기준 통일, S100 인쇄 페이지 오프셋(+16)은 manifest에 기록 | 인쇄 페이지 기준 | 평가(인용률 100%)의 자동 검증이 pdfplumber 페이지 인덱스와 직접 대조 가능해야 함. 인쇄 페이지 기준이면 문서마다 오프셋 계산이 검증 코드에 스며듦 |
| D27 | 환경 관리: **uv + venv** (pyproject.toml + uv.lock + .python-version), Docker는 MVP 제외 | Docker 컨테이너 | SQLite 파일 DB + 시스템 의존성 없음 → 컨테이너가 줄여줄 환경 편차가 애초에 없음. uv.lock으로 재현성 충분. docker-compose(backend+mcp 2서비스)는 D15 실전 연동 어필용으로 백로그 P14 |
