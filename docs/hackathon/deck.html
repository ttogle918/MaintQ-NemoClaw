MaintQ 는 설비 고장 진단부터 부품 발주 초안까지 도구로 잇는 보전 에이전트입니다. 이번 해커톤에서는 그 위에 새 기종 온보딩과 NVIDIA 런타임·샌드박스를 얹었습니다. 한 문장으로 말하면, 에이전트는 초안까지만 만들고 최종 결정은 사람이 합니다.
문제

새 기종이 들어오면, 매뉴얼은 영문 PDF 한 권뿐입니다

현장은 고장 코드를 한국어로 빨리 알아야 합니다. AI 번역을 그대로 믿으면 두 가지 사고가 납니다.

잘못된 진단

번역·추출이 틀린 고장 정의로 엉뚱한 조치를 합니다.

모르는 코드를 비슷한 코드로 추측하면 더 위험합니다.

잘못된 안전 문구

방전 대기 시간 같은 숫자가 틀리면 감전 사고로 이어집니다.

기존 기종의 값(예: 10분)을 새 기종에 그대로 쓰는 것도 같은 오류입니다.

설비 보전 현장에 새 기종이 들어오면 보통 영문 매뉴얼 PDF 하나만 있습니다. 여기서 AI 번역을 그대로 믿으면 두 가지 사고가 납니다. 하나는 틀린 정의로 잘못 진단하는 것이고, 다른 하나는 방전 대기 시간 같은 안전 수치가 틀리는 것입니다. 기존 기종의 10분을 새 기종에 그대로 쓰는 것도 같은 오류입니다.

4 · 진단
OpenClaw (NemoClaw)

확정된 코드만 진단합니다. 확정 전 코드는 추측 없이 A/S 로 안내합니다.

화면의 「승격」 = 이 발표의 「확정」 · 근거 D145~D147 · D150~D157

해법은 역할 분리입니다. 추출은 LLM 없이 결정적 코드가 하고, 한국어 초안은 샌드박스 안의 NAT 에이전트와 Nemotron 이 만들되 스테이징 테이블에만 씁니다. 확정과 안전 문구 승인은 사람이 합니다. 현장 진단 에이전트 OpenClaw 는 사람이 확정한 코드만 진단합니다. 화면에서는 확정을 「승격」이라고 부릅니다.
아키텍처

두 런타임, 한 개의 MCP 서버, 키 없는 샌드박스

호스트에는 같은 MCP 서버의 HTTP 입구가 두 개 있습니다. 8765 는 진단용 코어 7종, 8766 은 온보딩 전용 3종입니다. OpenClaw 샌드박스는 8765 의 /mcp 만, 그것도 node 실행 파일로만 부를 수 있고, NAT 샌드박스는 8766 만 엽니다. 두 샌드박스 모두 Nemotron 은 게이트웨이를 거쳐서만 부르며, API 키는 게이트웨이에만 있습니다.

실데이터 249행 전량 정규화 · 8코드 확정 · 안전 문구 1건 승인 · 전/후 녹화 · spikes 1,387건 · pytest 412건.

④ 커스터마이징·독창성

보안 설계 ① — 샌드박스가 막는다

에이전트가 틀려도 밖으로 못 나갑니다

샌드박스 안에 키 없음

환경변수에 키가 없는데 Nemotron 호출 성공. 키가 보이면 기동을 거부합니다. 이미지 파일 17,833개 스캔, 비밀값 0건.

egress 허용 목록

웹 콘솔 샌드박스는 외부 허용 0건. 다른 도메인은 전부 403 과 OCSF 로그(실행 파일·목적지)로 남습니다.

실행 파일·경로 단위 허용

OpenClaw 는 :8765/mcp 를 node 로만. 같은 주소를 curl 로 부르면 거부됩니다.

파일시스템 (Landlock)

/app 쓰기는 PermissionError 13. 쓰기는 /tmp 뿐입니다.

SUBMISSION §3.1~§3.4 · D143 · D151 · deploy/openshell/policy.yaml

첫 번째 층은 샌드박스입니다. 샌드박스 안에는 API 키가 없고, 키는 게이트웨이에만 있습니다. 나가는 연결은 허용 목록 밖이면 403 으로 막히고 로그가 남습니다. 허용된 MCP 주소도 node 실행 파일로만 부를 수 있어서, 같은 주소를 curl 로 부르면 거부됩니다.
보안 설계 ② — 서버와 DB 가 막는다

막는 건 에이전트의 판단이 아닙니다

DB 쓰기 가드

도구는 draft INSERT 만. UPDATE 는 트리거가, 읽기 전용 커넥션의 INSERT 는 DB 가 거부합니다.

주입 판정은 서버가

에이전트가 high 를 보내도 서버가 low + 플래그로 덮습니다. 합성 주입 픽스처 5/5.

안전 문구 fail-closed

사람이 승인한 DB 행에서만 나옵니다. 원문에 없는 숫자는 API 가 거부합니다(number_not_in_source).

신원은 서버가 읽는다

요청자는 LLM 파라미터가 아니라 X-User 헤더에서. 모르는 사용자면 초안을 만들지 않습니다.

SUBMISSION §3.5~§3.7 · §3.10 · D10 · D152 · D154 · D157

두 번째 층은 서버와 DB 입니다. AI 도구는 초안을 추가만 할 수 있고, 수정은 DB 트리거와 권한이 막습니다. 매뉴얼에 숨은 지시문 같은 주입 의심은 에이전트가 아니라 서버가 결정적으로 판정합니다. 안전 문구는 사람이 승인한 행에서만 나오며, 원문에 없는 숫자는 입력 단계에서 API 가 거부합니다.
쓰기 도구 4종

에이전트가 쓸 수 있는 건 초안뿐입니다

  • 커넥션을 대상별로 나눕니다. 섞으면 트리거·권한 잠금이 풀립니다.
  • 처분서 도구에는 override·reviewed_by 파라미터가 아예 없습니다.
  • 서명 때 근거 번들을 다시 계산해 다르면 409 evidence_changed.
에이전트의 쓰기 도구는 네 개뿐이고 모두 INSERT 만 합니다. 커넥션도 도구마다 따로 열어서 한 도구가 다른 테이블의 잠금을 풀지 못하게 했습니다. 처분서 도구에는 우회나 검토자를 채울 파라미터 자체가 없어서 모델이 채울 자리가 없습니다. 승인·서명·확정은 전부 사람 전용 API 에서만 일어납니다.
