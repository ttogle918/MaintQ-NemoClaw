# MaintQ 기획서 v1.0

## 1. 한 줄 정의

중소 제조공장 설비보전팀을 위한 AI 에이전트 — 인버터/PLC 에러코드 진단부터 부품 특정, 재고·견적 조회, 발주서 초안, 승인 워크플로우까지 하나의 대화로 연결한다.

## 2. 문제 정의 (As-Is)

에러 발생 시 현재 흐름:

```
에러코드 표시 → 정비사가 PDF/종이 매뉴얼 검색 (10~30분)
→ 원인 판단은 고참 정비사 경험(암묵지)에 의존
→ 부품 필요 시 자재담당에게 전화/메신저로 재고 확인
→ 없으면 공급사에 견적 전화
→ 엑셀 발주서 수기 작성 → 팀장 결재
```

문제: 단계마다 **사람이 바뀌고, 매체가 바뀌고(PDF→전화→엑셀), 대기가 발생**한다.
심화 문제: 숙련공 은퇴로 진단 노하우(암묵지)가 조직에서 사라지고 있다.

### 기존 대안과의 비교

| 대안 | 한계 |
|---|---|
| PDF/종이 매뉴얼 | 검색 느림, 진단 판단 불가, 발주 연결 없음 |
| 고참 정비사 | 암묵지 의존, 부재/퇴직 시 공백 |
| CMMS (설비보전관리시스템) | 이력·재고·발주를 **기록**할 뿐, "왜 떴고 뭘 점검하고 어떤 부품이 필요한지" **판단** 못함 |

> **포지셔닝: CMMS는 기록 시스템, 매뉴얼은 정적 문서다. MaintQ는 그 사이 — 진단이라는 판단 업무를 자동화하고, 판단 결과를 조달 액션까지 연결한다.**
> 부가 프레임: "신입 정비사도 고참처럼 진단하게 한다" (암묵지의 시스템화)

정직한 한계: 대기업용 스마트팩토리 솔루션 중 AI 진단을 결합하는 제품이 등장 중. MaintQ의 차별점은 **공개 매뉴얼 + LLM으로 중소공장도 구축 가능한 경량 접근**(가격/접근성).

## 3. 타겟 & 페르소나 (B2B)

타겟: 중소 제조공장 설비보전팀 (사내 도구 / B2B SaaS)

| 페르소나 | 역할 | 화면 |
|---|---|---|
| 정비사 김OO | 에러 입력 → 진단 확인 → 점검 → 발주 **요청** | 화면 A: 진단 콘솔 |
| 보전팀장 박OO | 근거 검토 → 발주 **승인/반려** | 화면 B: 승인 큐 |

진단자와 승인자의 역할 분리는 실제 조직 프로세스이며, human-in-the-loop이 이를 반영한다.

## 4. 가설 KPI (북극성 지표)

**고장 발생 → 발주 완료 리드타임: 30분+ → 5분**
(매뉴얼 검색 10~30분 + 재고 확인 전화 + 발주서 수기 작성 → 대화 한 세션)
목업 환경이므로 실측 불가, 가설 지표로 명시.

## 5. 핵심 기능 (MVP)

1. 에러코드 진단 — 룩업(정확 조회) + RAG(절차 서술) 이원화, 근거 페이지 인용 필수
2. 부품 특정 → 재고/안전재고 조회 → 공급사 견적 비교
3. 재고 없음 시 호환 대체품 분기 / 대체품도 없으면 에스컬레이션
4. 발주서 초안 생성 (draft만) → 승인 워크플로우 (팀장 전용)
5. ★ 반복 고장 감지 (30일 내 3회 → 근본원인 점검 모드 전환)
6. ★ 안전 가드레일 (위험 작업 시 매뉴얼 근거 안전 경고 필수)
7. 실행 trace 시각화 (도구 호출 타임라인 — 시그니처 화면)

## 6. Out of Scope (의도적 제외)

| 제외 항목 | 이유 | 확장 방향 |
|---|---|---|
| 예지보전(고장 예측) | 센서 시계열 ML은 별개 프로젝트 규모. "고장 발생 후" 대응에 집중 | 반복 감지 기능이 예지보전의 입구 |
| 실시간 PLC/설비 통신 | 에러코드는 사람이 텍스트 입력 | 사진 진단(백로그) → 설비 연동 |
| 실제 ERP/구매 연동 | 목업 DB + MCP | 도구 인터페이스를 실연동 가정 스키마로 설계, MCP 서버만 교체 |
| 다중 제조사 전체 커버 | LS일렉트릭 2기종(iG5A·S100) 한정. 깊이 > 넓이 | 기종 추가는 error_codes 적재만 |
| 결재/권한 시스템 | 승인은 역할 헤더 + 버튼으로 시뮬레이션 | SSO/조직 권한 연동 |

## 7. 평가 계획

에러코드 20개 테스트셋(`eval/testset.json`) 자동 실행:

| 지표 | 목표 |
|---|---|
| 부품 특정 정확률 | ≥ 90% |
| 근거 페이지 인용률 | 100% |
| 안전 경고 누락 | 0건 |
| 미지 코드 환각률 | 0% (S4: 추측 없이 한계 인정) |
| 권한 위반 차단 (정비사 approve → 403) | 100% |

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| 매뉴얼 표 파싱 실패 (최대 기술 리스크) | 표를 구조화 추출(JSON) → 룩업 도구로. RAG는 본문 서술만. M1에 버퍼 배정 |
| 매뉴얼 저작권 | 공개 자료지만 README에 출처 + 비상업/학습 목적 명시. 원본 PDF는 git 제외 |
| 안전 조언 책임 | 매뉴얼 원문 근거 + 페이지 인용 필수, AI 단독 판단 금지 원칙. 안전 경고 컴포넌트 분리 |
| API 비용 | 세션당 도구 호출 상한, 평가 실행 비용 사전 추정 |
