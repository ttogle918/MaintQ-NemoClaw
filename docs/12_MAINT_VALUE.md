# 보전 이력 · 자산가치 (Phase 2 설계)

> ⚠️ **MVP 범위 아님.** 착수 조건은 `11_ASSET_LIFECYCLE §8`과 동일하다.

**핵심 전환:** MaintQ가 이미 쌓고 있는 고장·정비 데이터가 **매각 시 값나가는 증빙**이 된다.
새로 수집할 데이터가 거의 없다는 게 이 문서의 강점이다.

**한 줄:** 하나의 데이터가 생애주기에서 세 번 값을 한다 — 가동 중엔 근본원인 판단(**S3**), 수리 시엔 투자 판단(**S1+**), 매각 시엔 증빙(**S10**).

---

## 1. 수리 이력은 세 갈래로 갈린다

산업 설비는 **수리를 전제로 설계**된다. 모듈화돼 있고, 부품 단위 교체가 정상 관행이며, 수명이 20~30년이라 그 사이 오버홀이 들어가는 게 당연하다. 그래서 "고쳤다"가 이례적 사건이 아니라 **정상적 관리의 증거**로 읽힌다.

```
수리 이력
 ├─ 소모품 교체 (필터·벨트·오일)      → 신뢰도 가점 (관리 수준의 증거)
 ├─ 핵심부품 갱신 (스핀들·볼스크류·감속기) → 잔존수명 회복 (가격에 직접 반영)
 └─ 반복고장·사고 (동일부위 재발·충돌)  → 감점 (근본원인 미해결)
```

### 흔한 오해 두 가지

- ❌ **"차의 사고이력과 반대다"** — 아니다. 설비도 충돌·사고 이력은 마이너스다. 베드·주축 정렬이 영구히 틀어지면 정밀도가 회복되지 않는다. 차도 타이밍벨트 교체·오버홀 기록은 플러스다. **차이는 정도이지 방향이 아니다.**
- ❌ **"고친 게 많을수록 좋다"** — 아니다. 같은 부위 반복 교체는 근본 원인 미해결 또는 혹사 신호다. **기존 S3(동일 에러 30일 3회, D2·D29)와 정확히 맞물린다.**

두 번째가 설계상 중요하다. MVP에서 이미 만드는 `get_error_history`의 `repeated` 판정이 **감점 신호로 재사용**된다. 새 로직이 아니다.

## 2. 보전지표

| 지표 | 산식 | 거래 시 의미 |
|---|---|---|
| MTBF (평균 고장 간격) | 총 가동시간 ÷ 고장 횟수 | **절대값보다 추세** |
| MTTR (평균 수리 시간) | 총 수리시간 ÷ 수리 횟수 | 부품 조달 난이도의 대리지표 |
| 가용도 | MTBF ÷ (MTBF + MTTR) | 실질 가동 가능성 |
| 예방보전 비율 | 계획정비 ÷ 전체정비 | **매수자가 가장 신뢰하는 지표** |
| 누적 수리비 / 취득원가 | — | 높으면 교체 신호 |
| 부품별 경과 주기 | 최근 교체일 ~ 현재 | 다음 교체 시점 예측 |

**MTBF 추세** — 최근 1년이 이전 대비 하락 중이면 마모 가속 구간 진입. 유지되면 안정 구간. 잔존 수명을 가장 직접적으로 말한다.

**예방보전 비율** — 사후정비만 했다면 고장 날 때까지 방치했다는 뜻. 정비 기록이 시계열로 남아야 성립하므로 **조작이 어렵다.**

### OEE는 거래 지표로 쓰지 않는다 (D64)

OEE = 가동률 × 성능가동률 × 양품률인데, 이 중 설비 자체 성능에 좌우되는 건 일부다. 나머지는 생산 계획·작업자 숙련도·자재 품질·금형 상태에 달려 있다. **같은 설비를 다른 공장에 옮기면 OEE는 완전히 달라진다. 재현되지 않는 숫자는 근거가 못 된다.**

실무적으로도 매도인은 제출할 유인이 없고(낮으면 불리, 높아도 값을 더 받지 못함), 매수인은 MES 로그 없이 검증할 수 없다.

**대신 OEE의 원재료는 확실히 본다** — 누적 가동시간, 스핀들 시간, 샷 수, 알람 이력. 컨트롤러에 남고 조작이 어렵고 마모도를 직접 반영한다.

참고치로 표시할 경우 **"매도인 환경 기준, 이전 후 재현 미보장"** 고지를 붙인다.

## 3. S1+ — 수리 판단에 자산가치 반영

MVP의 S1은 "진단 → 부품 특정 → 발주"로 끝난다. Phase 2에서 발주 전에 **수리 / 교체 / 매각** 3지 판단이 들어간다.

```json
{
  "equipment_id": "INV-L3-01",
  "failed_part": "FAN-IG5-01",
  "part_class": "CRITICAL",              // CONSUMABLE | CRITICAL
  "repair_cost": 8500000,
  "book_value": 63333333,
  "market_value_before": 42000000,
  "market_value_after": 51000000,
  "value_recovery": 9000000,
  "recovery_ratio": 1.06,
  "mtbf_trend": "declining",
  "repeat_failure": false,               // get_error_history 재사용
  "cumulative_repair_ratio": 0.21,
  "verdict": "REPAIR_RECOMMENDED",
  "alternatives": [
    {"option": "REPLACE",     "cost": 120000000, "note": "신규 취득 + 기존 매각"},
    {"option": "SELL_AS_IS",  "proceeds": 42000000, "note": "수리 없이 현상 매각"}
  ],
  "disclaimer": "시장가는 목업 잔가곡선 기반 추정치. 실거래가와 다를 수 있음"
}
```

**`repeat_failure == true`면 3지 판단보다 근본원인 점검이 먼저다** — S3 우선순위 유지(D2). 발주 보류(`po_card` variant:`hold`, D35)가 그대로 적용된다.

### 회계 처리 연결

- 성능 향상·내용연수 연장을 수반하는 지출 = **자본적 지출** → 자산 가산, 재상각, 장부가액 상승
- 원상 회복 수준의 수리 = **수익적 지출** → 당기 비용

이 구분이 실무에서 가장 논쟁이 잦다. 경계 사안은 **`유보` + 전문가 확인 안내**로 반환하고 단정하지 않는다(D62).

```
classify_expenditure(part_class, repair_scope, amount)
  → CAPITAL | REVENUE | 유보  + law_refs[]
```

## 4. 시장가 추정의 한계 (D65)

기종별 잔가 곡선의 공개 데이터가 부족하다. **목업 테이블로 두고 추정치임을 반드시 고지한다.**

D31이 `unit_price`를 도구 입력이 아닌 `supplier_parts` 조회 스냅샷으로 만든 것과 같은 논리다 — LLM이 금액을 지어낼 경로를 만들지 않는다. 다만 잔가는 조회할 원천 자체가 없으므로, **없는 정확도를 있는 척하지 않는 것**이 유일한 정직한 처리다.

가격 영향 요인 중 **기술적 진부화가 경과연수보다 클 때가 많다** — 제어기 세대, 부품 단종, 통신 규격, 제조사 존속. 상태가 멀쩡해도 부품이 단종이면 값이 급락한다. `parts.discontinued`(D20)가 이미 있으므로 설비 단위로 올리면 된다.

## 5. 중고 거래 배경

설비는 **중고 거래가 활발하다.**

| 근거 | 내용 |
|---|---|
| 설비 수명 | 20~30년 → 재판매 시장 성립 |
| 신품 리드타임 | 공작기계·사출기 등 납기 수개월~1년 → 급하면 중고가 유일 대안 |
| 단종 부품 확보 | 동일 기종을 통째로 매입해 부품 소스로 |
| 유통 경로 | 전문 딜러 · 산업장비 경매 · 온라인 마켓 · 리스 반환자산 · 폐업 일괄매각 |

### 신품 거래와 다른 점

- **현상인도(as-is)가 기본.** 하자담보책임을 특약으로 배제하는 경우가 많아 **실사가 사실상 유일한 방어선**이다.
- **권리관계 확인이 불완전하다.** 동산은 등기가 없다 → `11_ASSET_LIFECYCLE §6 S18`.
- **감가상각 명세가 외부 제출 산출물이 된다.** 매수자(사용 연수 검증)·금융기관(담보 감정)·세무(처분손익 근거) 셋이 받는다.
- **안전검사를 다시 받아야 한다.** 이전 설치 후 재검사 미이행 시 사용 불가.
- **이전 비용이 과소평가된다.** 해체·중량물 운송·반입 경로(크레인·바닥하중·출입구)·설치·유틸리티 공사·시운전. 대형 설비는 합계가 설비가에 육박하기도 한다.

## 6. 실사 체크리스트 (9개 카테고리)

`verify_ownership`을 권리관계 전용이 아니라 전체 체크리스트로 만든다.

| 카테고리 | 항목 |
|---|---|
| 물리적 상태 | 정밀도, 진동·소음, 누유, 전장부, 베드·가이드 마모 |
| 가동 이력 | 누적 가동시간, 스핀들 시간, 알람 이력, 교대 패턴, 가공 소재 |
| **정비 이력** | 정기점검 기록, 핵심부품 교체, 오버홀, **반복 고장 패턴** |
| 기술적 진부화 | 제어기 세대, 부품 단종, 통신 규격, 제조사 존속 |
| 권리관계 | 소유자, 담보, 리스, 압류 |
| 법정 요건 | 안전검사, 안전인증, 환경 규제 |
| 재무·회계 | 감가상각 명세, 매도인 세액공제, 내용연수 결정 |
| 시장·가격 | 동일 기종 거래가, 감정평가서, 매도 사유 |
| 이전 비용 | 해체·운송·반입경로·설치·시운전 |

**법정 표준 양식은 없다.** 회사·딜러·경매사마다 자체 양식을 쓴다. 다만 **안전검사 항목은 법정**이라 고시에서 그대로 가져올 수 있다. 그래서 템플릿을 `{법정필수항목[], 사내항목[]}`으로 나누고 법정 항목은 룰 카탈로그에서 자동 주입한다 — "이 항목은 왜 있나"에 답이 된다.

매도인이 정비 이력을 제공하지 않으면 **그 자체가 리스크 항목**이 된다(`unverified`).

## 7. S19 — 수리 완료 → 증빙 서명

나중에 팔 때 증명하려면 **그때 서류가 있어야 한다.** 이 시나리오가 없으면 S10의 증빙 패키지가 성립하지 않는다.

```json
{
  "repair_id": "REP-2026-0311",
  "equipment_id": "INV-L3-01",
  "error_code": "OHT", "model": "iG5A",       // po_drafts와 같은 복합키 (D33)
  "part_class": "CRITICAL",
  "parts": [{"part_no": "FAN-IG5-01", "serial": "SN-88214", "qty": 2}],
  "work_type": "PLANNED",                      // PLANNED | UNPLANNED — 필수
  "expenditure_class": "CAPITAL",
  "cost": 8500000,
  "performed_by": "tech-01", "verified_by": "mgr-01",   // users FK (D41), ID (D36)
  "signed_at": "2026-08-02T10:14:00Z",         // UTC (D39)
  "record_hash": "sha256:7c4a…"
}
```

**`work_type` 필수가 핵심이다.** 이 필드 하나가 나중에 가장 값나가는 지표(예방보전 비율)를 만든다. 미기재는 거부.

서명된 레코드는 수정 불가. 정정은 정정 레코드 추가(append-only). D29가 "자동 기록하면 count가 질문 횟수가 된다"고 판단한 것과 같은 이유로, **명시적 액션으로만** 기록한다.

## 8. S10 확장 — 처분 증빙 패키지

`generate_disposal_document` 출력에 포함:

- **정비 이력 요약서** — 수리 건별 부품·일시·등급, 서명 레코드 참조
- **보전지표 리포트** — MTBF 추세, 예방보전 비율, 누적 수리비
- **핵심부품 갱신 내역** — 갱신 부품·일시·시리얼 (**가격에 직접 영향**)
- **감가상각 명세** — 연도별 상각액·누계·장부가액

넷이 묶여 증빙 패키지가 되고 근거 번들에 포함돼 서명 시 고정된다.

## 11. 가드레일

- 시장가 **추정치 고지 강제** — 단정적 금액 표현 차단 (D65)
- 자본적/수익적 **경계 사안은 유보** (D62)
- **반복 고장 시 3지 판단보다 근본원인 모드 우선** (S3 유지, D2)
- **서명 없는 수리 레코드는 지표 계산 제외**
- OEE는 **거래 판정에 사용 금지**, 참고치 표시 시 고지 (D64)
- `PARTIAL`은 `VERIFIED`로 승격 불가
