## 붙여넣을 프롬프트

```
B2B 제조 현장용 AI 에이전트 "MaintQ"의 웹 UI를 디자인해줘.
첨부한 와이어프레임(03_WIREFRAME.html)의 레이아웃과 주석 7개를 그대로 따르되, 하이파이로 올려줘.

## 제품 맥락
- 인버터/PLC 에러 진단 → 부품 재고 조회 → 발주 승인까지 처리하는 사내 도구
- 사용자 2명: 정비사(진단 콘솔, 화면 A), 보전팀장(승인 큐, 화면 B)
- 이 제품의 주인공은 채팅이 아니라 우측 "실행 로그(trace) 패널" — AI가 어떤
  도구를 왜 호출했는지 타임라인으로 보여주는 영역. 여기에 시각적 무게를 실어줘.

## 디자인 방향
- 무드: 산업용 콘솔. 장식 없이 밀도 있게, 관제 시스템 같은 신뢰감.
  소비자 앱처럼 둥글둥글하거나 그라데이션 쓰지 말 것
- 라이트 테마 기본 (공장 사무실·현장 밝은 조명 환경)
- 컬러: 중립 그레이 베이스 + 포인트 2색만
  - 안전/경고/긴급: 산업 안전 오렌지 #E8590C — 오직 안전 경고 블록,
    긴급 뱃지, 반려 버튼, 분기 발생 표시에만 사용 (남용 금지)
  - trace/시스템 동작: 딥 블루 #1C5D99 — 도구 호출 타임라인, 진행 상태
- 타이포: 본문 Pretendard, 도구 이름·코드·품번·에러코드는 모노스페이스
- 데이터 밀도 높게: 여백 과다 금지, 표와 카드 중심

## 화면 A — 진단 콘솔 (정비사)
- 좌 채팅(55%) + 우 trace 패널(45%), 상단 헤더에 라인/장비 선택 칩
- 컴포넌트: 사용자/AI 말풍선, 인용 페이지 칩(매뉴얼 p.202 형태),
  안전 경고 블록(오렌지 테두리, 일반 말풍선과 확실히 구분되는 전용 컴포넌트),
  발주서 초안 카드(품목/수량/공급사/단가 + "팀장 승인 요청" 버튼만 — 확정 버튼 없음)
- 위 3종(안전 경고 블록·발주 카드·인용 칩)은 채팅 텍스트가 아니라 **SSE block
  이벤트(type: safety / po_card / citation)로 도착하는 전용 렌더 컴포넌트** —
  텍스트 스트림 중간에 삽입되므로, 말풍선 흐름 사이에 끼어들어도 자연스러운 형태로
- 변형 상태: **S3(반복 고장) 대화에서는 발주 카드 자리에 "발주 보류 — 원인 확정 후
  진행" 상태 블록이 표시됨** (발주 카드 아님 — 원인 확정 전 발주 금지). 이 상태
  블록의 디자인도 포함할 것
- trace 패널: 탭 3개(실행 로그/근거 문서/발주 이력), 세로 타임라인,
  스텝마다 도구명(모노스페이스)+입력요약+상태(✓ 완료/⚠ 분기/pending)+소요시간
- 상태 디자인 포함: 도구 실행 중(스피너/펄스), 분기 발생(오렌지 점), 대기

## 화면 B — 승인 큐 (팀장)
- 좌 큐 리스트(긴급/일반 뱃지) + 우 상세
- 상세: 근거 요약 카드(ERROR/SYMPTOMS/DIAGNOSIS/INVENTORY/NOTES/TRACE 6행, 인용 칩 포함
  — SYMPTOMS·NOTES는 po_drafts.evidence JSON에서 옴, D34),
  공급사 비교 카드 2개(추천에 강조 테두리, MOQ 미달은 카드에 명시), 하단 승인(프라이머리)/반려(오렌지 아웃라인)
- 빈 상태 디자인 포함: "승인 대기 없음"

## 산출물
- 화면 A, B 각 1개 + 안전 경고 블록/발주 카드/trace 스텝의 컴포넌트 상세
- 데스크톱 1440px 기준. 카피는 와이어프레임의 한국어 그대로 사용
```

## 결과물 받고 나서 검수 체크리스트

- [ ] 오렌지가 안전/긴급 외 장식으로 새어나가지 않았는지 (오렌지 남용 = 경고 무감각화)
- [ ] 발주 카드에 "확정" 류 버튼이 생기지 않았는지 (승인 요청만 있어야 함 — D10/D18)
- [ ] S3 대화 예시에 발주 카드가 없는지 — "발주 보류" 상태 블록이어야 함 (02_SCENARIOS S3)
- [ ] 안전 경고가 말풍선 텍스트에 섞이지 않고 별도 블록으로 렌더되는지 (SSE block 이벤트 대응 — D22)
- [ ] trace 패널이 채팅보다 시각적으로 죽지 않았는지
- [ ] 인용 페이지 칩이 모든 진단 말풍선에 들어갔는지
- [ ] 인용 칩이 **인쇄 페이지 우선 + PDF 병기** 형식인지 (`S100 매뉴얼 p.400 (PDF p.416)` — D32).
      물리 페이지만 노출하면 정비사가 실제 매뉴얼에서 못 찾는다
- [ ] 안전 경고 블록이 스크롤 중에도 눈에 걸리는 강도인지
- [ ] 역할 전환이 **라우트**(`/technician`·`/manager`)인지, 클라이언트 상태 토글이 아닌지 —
      토글이면 "정비사 approve → 403"을 시연할 수 없다
- [ ] 발주 보류 블록이 발주 카드와 시각적으로 구분되는지 (`po_card` variant:`hold`, D35)
- 통과하면 frontend/ 구현의 디자인 스펙으로 채택, docs/에 산출물 링크 추가
